# 17 · DHT 节点身份与信任方案（"凭什么信你"）

> 立项背景：节点模式要从"客户端连种子"改为"每个节点向 DHT 宣告自己"（07 §5 第③层的落地）。
> 一旦人人可宣告，就必须回答一个协议问题：**收到一条宣告，凭什么相信它是正主，而不是冒充者？**
> 本文给出可实施的设计。核心结论：去中心化系统里"正主"无法被绝对证明，只能被**验证 + 背书 + 付费**，
> 因此方案是"三层可叠加的锚"+ "信任图"，且**根信任是配置项、不是代码常量**。

---

## 1. 三条必须分开的"信任"

把三件事混在一起谈，方案一定谈不清：

| 问题 | 含义 | 现有能力 |
|---|---|---|
| **A. 身份自证** | "这条宣告确实是我本人发的，没被改过" | ✅ 已有：ed25519 签名 + `node_id = SHA256(pubkey)` |
| **B. 名字归属** | "`seed.wgp.dev` 这个名字凭什么归这个公钥" | ❌ 缺 |
| **C. 可信度** | "这个节点值不值得被我当中继/观察者/存储" | ❌ 缺 |

A 已经有了（[advertise.rs](../kernel/wgp-dht/src/advertise.rs)、[id.rs](../kernel/wgp-dht/src/id.rs)），
B 和 C 才是"正主"问题的真正所在。**本方案只补 B 和 C，不动 A。**

## 2. 威胁模型

| 攻击 | 说明 | 对应防线 |
|---|---|---|
| **冒充既有节点** | 伪造 `node_id` 抢占别人在路由表里的位置 | A 已解决：没有私钥签不出宣告 |
| **冒名顶替（新身份）** | 自己生成密钥对，把节点叫 `seed.wgp.dev` | B：名字要能被独立验证 |
| **女巫攻击（sybil）** | 批量生成 N 个身份，占满路由表/投票 | L3 准入成本 + 路由表卫生 |
| **日蚀攻击（eclipse）** | 把受害者的桶全填成自己的节点，切断它与真实网络的联系 | 每 /24 限入 + 随机化刷新 |
| **地址投毒** | 宣告一个假地址，把流量引到自己这儿（中间人或黑洞） | 宣告签名绑定地址 + 探活校验 |
| **重放** | 拿旧宣告反复注册 | 报文带 epoch/时间窗，接收端单调递增校验 |

## 3. 设计原则

1. **身份自持**：节点自己生成密钥，没有任何"发证机构"审批。谁都能加入——但能不能被**信**是另一回事。
2. **根信任可替换**：客户端内置的是**若干公钥指纹 / 域名**（`trust_roots`），不是 IP、不是写死的官方地址。
   别人 fork 我们的代码，换成自己的根，就是一个独立运行的网络——**这正是"我们不维护了、别人还能用"的技术前提**。
3. **协议里不出现"官方"二字**：官方节点只是默认 `trust_roots` 里的几项配置，和第三方节点走完全相同的验证路径。
4. **信任可衰减、可撤销**：所有背书带有效期，不续签自然失效（等价于"持续维护"）。

## 4. 方案：四层

### L0 · 身份自证（已有，不改）

- 长期密钥：ed25519，持久化在 `node_identity.key`（32B 种子）。
- `node_id = SHA256(pubkey)`，天然自证绑定。
- 宣告与 RPC 响应均带签名；PING/PONG 交换公钥并校验 `SHA256(pk) == node_id`。

### L1 · 名字锚定（"正主"）——三把锚，可叠加

节点要在宣告里说明"我叫什么、这个名字凭什么归我"。三种锚定方式，**按可信度递减、按部署成本递增**：

#### 锚 ①：域名锚（DNS TXT）——最强，且不需要我们维护

```
_wgp.seed.example.com.  IN TXT  "wgp1=<base32(ed25519_pubkey)>"
```

- **正主 = 控制该域名的人**。域名所有权是全世界通行的既成信任，不需要我们做 CA，也不需要我们维护。
- 任何客户端都能独立验证：查 TXT → 比对公钥 → 比对 node_id。
- 换 IP 不影响信任（信任绑公钥，不绑地址）。
- 缺点：需要用户有个域名（几块钱/年）。

#### 锚 ②：背书锚（已有节点签名）——零门槛，靠社交图

```
Endorsement {
    subject_pubkey : [u8;32]   // 被背书的节点
    endorser_pubkey: [u8;32]   // 背书人（自己已有可信度）
    scope          : u8        // 允许的角色位：relay/observer/store/bootstrap
    issued_at      : u64       // 毫秒
    expires_at     : u64       // 建议 30 天，需续签
    sig            : [u8;64]   // endorser 签名
}
```
共 32+32+1+8+8+64 = **145B**，存 DHT KV：`key = SHA256("wgp/endorse/v1" ‖ subject_pubkey)`，值为背书记录列表。

- 官方初始的 3 个节点互为背书，构成"根"；新节点找它们要背书即可入网。
- **背书是有限的**：每节点每 24h 最多签 N 张（本地限制），且背书人自己掉信任会连带影响下游。

#### 锚 ③：TOFU（首次使用信任）——兜底，不推荐单独使用

第一次见到这个 node_id 就记住（本地 `known_nodes.json`）；之后再看到同名的不同公钥 → **告警 + 拒绝自动覆盖**。
适合"我自己的两台机器互连"这种场景，不适合公共节点。

> 三把锚的组合：**① 优先、② 兜底、③ 兜自己的私活**。三者都由同一套 `TrustStore` 统一评分。

### L2 · 信任图与权重

```
trust_score(node) = Σ over endorsers e  w(e) × decay(hops(e → root))

w(root)      = 1.00        （trust_roots 里列出的指纹/域名）
w(depth 1)   = 0.50        （根直接背书的）
w(depth 2)   = 0.25
w(depth ≥3)  = 0.125       （封顶，不再衰减，避免长链洗白）
```

- `trust_score ≥ 1.0` → 可当 `bootstrap`（给别人当种子）
- `≥ 0.5` → 可当 `relay` / `observer` / `store`
- `< 0.5` → 只能当普通成员（能加入、能被连，但不被依赖）

这条规则的含义：**"可信"不是自称的，是别人给的，并且要够多人才算数。**

### L3 · 准入成本与路由表卫生

| 措施 | 目的 | 代价 |
|---|---|---|
| **轻量 PoW**：`node_id` 前 16–20 bit 为 0 才允许入路由表 | 让"造 10 万个身份"从秒级变成小时级 | 每节点启动时算 1 次，几秒 |
| **每 /24 限入 K 个**（K=2~4） | 抗日蚀 | 无 |
| **入表需双向 PING 成功 + 签名校验** | 抗地址投毒 | 无 |
| **桶随机化刷新**（每 10 分钟挑一个桶重新 FIND_NODE） | 抗日蚀 | 少量流量，受预算闸门约束（H6） |

## 5. 线格式改动（具体到字节）

现有 `SeedAdvertise` 定长 91B：

```
[0..2]  magic        [2] type=0x20
[3..7]  addr_v4      [7..9] dht_port   [9..11] stun_port
[11]    priority     [12] flags
[13..27] 14B 保留（当前全 0）   ← 正好放新字段
[27..91] ed25519 签名(64B)
```

**改动（向后兼容）**：把 14B 保留位定义为

```
[13..21] epoch_ms 低 64 位   （抗重放；接收端要求单调递增）
[21..23] endorse_count       （背书数，仅作提示，不作信任依据）
[23..27] name_hash_prefix    （SHA256(名字) 前 4B，供快速匹配）
```

- 老节点读到非零保留位 → 按现有语义忽略（签名覆盖到 [0..27]，所以改动会自然让老节点验签失败……
  **因此需同时把 `PROTO_VERSION` +1，按版本分支解析**，或另开 `type=0x21` 的新报文。
  **推荐后者**：`SeedAdvertiseV2 (type=0x21, 115B)`，带 `subject_pubkey(32)`，彻底摆脱"要额外信道取公钥"的约束。
- 背书记录**不进**广告报文（太长），走 DHT KV。

## 6. 代码落点

| 文件 | 改动 |
|---|---|
| `kernel/wgp-proto/src/packet.rs` | 新增 `seed_advertise_v2`（115B，含公钥 + epoch + name_hash） |
| `kernel/wgp-proto/src/consts.rs` | `PROTO_VERSION` 升级 + `PROTO_DOMAIN_*` 域分隔常量 |
| `kernel/wgp-dht/src/advertise.rs` | `sign_advertise_v2` / `verify_advertise_v2`（不再依赖外部取公钥） |
| `kernel/wgp-dht/src/trust.rs`（新） | `TrustStore`：锚点、背书、评分、有效期、TOFU 记录持久化 |
| `kernel/wgp-dht/src/node.rs` | 启动后周期广播宣告；入站验签 → `TrustStore::observe`；入表前过 PoW 与 /24 限制 |
| `kernel/wgp-dht/src/kbucket.rs` | 桶分裂 + 老化 + /24 计数（当前是"满了拒入"） |
| `server/wgp-node/src/server.rs` | `--name` / `--trust-root` / `--pow-bits` 参数；启动时打印"我的指纹 + 该填的 DNS TXT" |
| `client/wgp-client/src/main.rs` | `wgp-client trust list/add/endorse` 三个子命令 |

**信任根的存储**：`trust_roots.toml`（随发行版附带默认值），格式：

```toml
# 官方默认根（仅是配置，协议里没有任何特权）
[[root]]
domain = "wgp.dev"            # 走锚①：查 _wgp.wgp.dev 的 TXT
[[root]]
pubkey = "b3f1:9a2c:...:7e04" # 走锚②：直接写公钥指纹
```

## 7. 分阶段实施

| 阶段 | 内容 | 工作量 | 上线后能看到什么 |
|---|---|---|---|
| **P0** | 广播 + 接收 `AdvertiseV2`；`TrustStore` 只做 TOFU + 静态 `trust_roots` | **2–3 天** | 节点自动互相发现，不再依赖手工种子清单 |
| **P1** | 背书 RPC + KV 存储 + 评分；`endorse` 子命令 | **3–5 天** | 官方节点能给新节点背书；可信节点自动获得 relay 权限 |
| **P2** | 域名锚（DNS TXT 校验）+ PoW + 路由表 /24 与分桶 | **5–7 天** | 抗 sybil/日蚀；运营者可用自己的域名声明正主 |

P0 做完就已经解决"节点模式改成 DHT 节点"：**宣告接线 + 互相发现**。P1/P2 是把"可信"补齐。

## 8. 待拍板的问题

1. **P0 阶段先不校验信任**：任何人都能宣告，先跑通发现链路。可接受吗？（我认为可以——早期用户少，滥用动力低。）
2. **官方根用哪种锚**：域名锚（需要买个域名，但最正规）还是纯背书锚（零成本，但"官方"只是"三个互相背书的节点"）？
3. **PoW 位数**：16 bit ≈ 手机 1 秒、服务器 0.05 秒；20 bit ≈ 手机 16 秒。取 18 bit 折中？
4. **背书有效期**：30 天续签，对家用宽带的贡献节点是否太频繁？

## 9. 与 EasyTier 的关系

本方案与 ET 兼容**互不依赖**：ET 桥接解决"和外部网络互通"，本方案解决"自己网络内部怎么互信地发现"。
若将来要互通 ET 公共节点，只需在 `TrustStore` 里加一个锚类型（`easytier-public-node`），评分逻辑不变。
