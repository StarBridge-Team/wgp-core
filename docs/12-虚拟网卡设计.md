# 十二、虚拟网卡设计（独立模块）

**状态**：设计定稿（独立可选模块，不进入 WGP 内核）
**来源**：flash-max-优化增强.md §五 提炼；对齐 V2《虚拟网卡与协议栈统一》设计
**决策记录**（2026-09-06）：虚拟网卡实现方案先行文档化；采用 TAP 方案（Windows 主选 TAP-Windows Adapter V9，兼容性备选 Wintun）；模块独立于内核，通过内核暴露的通道抽象接口接入。

---

## 1. 定位与边界

- **目标**：向操作系统注册一张虚拟网络接口，把 P2P 通道封装为标准 IPv4/IPv6 网络层。任意支持 TCP/IP 的应用（浏览器、游戏、SSH、FTP）零改造走 P2P 直连，应用完全无感知。
- **边界**：
  - 独立可选模块，**内核（打洞/加密/信令/端口转发）不依赖本模块**；
  - 本模块依赖内核暴露的通道抽象接口（wgp-channel 的 Channel trait）；
  - 内核硬约束不受影响：仍无中继、业务数据端到端加密、协议核心业务无关。

## 2. 双层架构

```text
┌─────────────────────────────────────────────┐
│  应用层（游戏/浏览器/SSH/任意 TCP-IP 程序）  │
├─────────────────────────────────────────────┤
│  标准 Socket API → 操作系统路由表            │
├─────────────────────────────────────────────┤
│  虚拟网卡层：TAP 设备（10.77.0.x/24）        │  ← 模块 A
├─────────────────────────────────────────────┤
│  协议栈统一层：IP 包 ↔ P2P 帧转换            │  ← 模块 B
├─────────────────────────────────────────────┤
│  加密层（AES-256-GCM，复用内核 wgp-crypto）  │
├─────────────────────────────────────────────┤
│  P2P 通道层（复用内核 wgp-channel）          │
├─────────────────────────────────────────────┤
│  物理网卡                                    │
└─────────────────────────────────────────────┘
```

**关键设计**：虚拟网卡层（让操作系统看到一张网卡）与协议栈统一层（IP 包与 P2P 帧互转）是两个独立模块，通过内部接口连接，可独立替换。

## 3. 虚拟网卡（TAP）生命周期

```text
1. 创建虚拟网卡
   ├─ Windows: TAP-Windows Adapter V9（OpenVPN 驱动，安装时需管理员）
   │           兼容性备选: Wintun（Windows 10 1803+，驱动更轻）
   ├─ Linux:   /dev/net/tun + IFF_TAP（需 root 或 CAP_NET_ADMIN）
   └─ macOS:   utun（TUN 模式，手动封装 14B 以太网帧头模拟 TAP）
2. 配置 IP 地址
   └─ 100.64.0.0/10，地址由 room_id + PeerId 联合哈希派生（见 §4）
3. 启动读写循环
   ├─ 读: 从 TAP 读取操作系统发来的 IP 包 → 交协议栈统一层
   └─ 写: 从协议栈统一层接收 P2P 帧 → 还原为 IP 包 → 写入 TAP
4. 销毁虚拟网卡
   └─ 连接断开时自动清理
```

### 平台实现矩阵

| 平台 | 实现 | 权限 | 备选 |
|------|------|------|------|
| Windows | TAP-Windows Adapter V9 | 安装时需管理员 | Wintun（无管理员/兼容性场景） |
| Linux | /dev/net/tun + IFF_TAP | root / CAP_NET_ADMIN | `ip tuntap` + sudo 脚本 |
| macOS | utun | 无需管理员 | 手动封装以太网帧头 |

### 地址分配方案

```text
网段:      100.64.0.0/10
地址格式:  100.{subnet}.{host_h}.{host_l}
subnet:    64 + room_id 高 6 位（room_id 为 32 位），房间即独立 /24
host:      SHA256(room_id || PeerId) 低 16 位，冲突检测自动重分配

特性:
  - 不同房间天然隔离在不同 /24 子网，P2P 房间即虚拟局域网
  - 虚拟 IP 与 PeerId 密码学绑定（SHA256 原像不可逆），用于防 IP 欺骗
  - IP 冲突: 哈希 + 冲突检测 + 自动重分配
```

## 4. 协议栈统一层（IP 包 ↔ P2P 帧）

### 4.1 P2P 帧封装

```text
+--------+--------+--------+--------+
| Magic  | Type   | Length | Flags  |
| (2B)   | (1B)   | (2B)   | (1B)   |
+--------+--------+--------+--------+
| SeqNum | AckNum | WinSize| 保留    |
| (1B)   | (1B)   | (1B)   | (1B)   |
+--------+--------+--------+--------+
| 原始 IP 包（完整）                  |
+-------------------------------------+
| AuthTag（AES-GCM 16B）              |
+-------------------------------------+
```

- Magic 等字段取值遵循 08 规范 §7.4：由 session_key HKDF 派生，每会话唯一，无固定指纹。

### 4.2 IP 协议类型映射

| IP 协议 | P2P Type | 说明 |
|---------|----------|------|
| TCP | 0x01 | 可靠传输 |
| UDP | 0x02 | 不可靠传输（游戏/实时流量原样透传） |
| ICMP | 0x03 | 虚拟网内 `ping 100.96.x.x` 可用 |
| IGMP | 0x04 | 多播（预留） |
| ARP | 0x05 | 虚拟局域网 ARP 解析 |

### 4.3 ARP 虚拟化

```text
标准 ARP:  广播 "谁是 100.96.0.100？" → 回复 MAC 地址
虚拟 ARP:  广播 "谁是 100.96.0.100？" → 协议栈统一层查 IP→PeerId 映射
           → 虚拟 MAC = SHA256(PeerId)[0..6]（同一 Peer 的 MAC 固定）
```

### 4.4 MTU 处理

```text
物理网卡 MTU 1500B
- IP 头 20B - UDP 头 8B - WGP 帧头 8B - AuthTag 16B = 1448B

虚拟网卡 MTU = 1448B
超限处理: IPv4 标准分片（Fragment Offset），接收端自动重组，5s 超时丢弃
```

## 5. 安全性

1. **网段隔离**：仅处理目标 IP 在 100.64.0.0/10 内的流量，不注册默认路由，不影响正常上网。
2. **加密范围**：整个 IP 包（含 IP 头）作为 AES-GCM 明文加密——对端地址与协议类型对中间人不可见。
3. **防 IP 欺骗**：接收端重算 `SHA256(room_id || PeerId)` 校验源 IP 与声称 PeerId 的绑定关系，不匹配即丢弃并告警。

## 6. 与内核的接口

1. **通道抽象**：内核 wgp-channel 提供 Channel trait（send_frame / recv_frame / peer_map），虚拟网卡模块作为该接口的消费者，反向依赖禁止进入内核。
2. **能力协商**：信令握手阶段位掩码 Bit0 = 虚拟网卡支持。协商规则：
   - 双端均支持 → 虚拟网卡模式
   - 任一方不支持 → 自动降级为端口转发模式（11 号文档）或 V1 私有协议模式
3. **无管理员权限降级**：自动切换用户态代理模式（应用 → 127.0.0.1:port → 协议栈），配合环境变量注入（HTTP_PROXY/SOCKS_PROXY）或 PAC 自动代理脚本，仅 P2P 流量走代理。

## 7. 交付与验证

- **交付形态**：独立 crate（如 wgp-tap），feature 门控，不进入内核 workspace 的必编译路径。
- **验收标准**：
  1. MC Java/基岩版等标准 socket 应用通过虚拟网卡 IP 完成联机；
  2. `ping 100.96.x.x` 经 P2P 通道往返（ICMP 透传）；
  3. 无管理员权限环境自动降级代理模式可用；
  4. 双端能力协商降级路径（虚拟网卡 ↔ 端口转发切换）无中断。
- **风险与应对**：

| 风险 | 应对 |
|------|------|
| TAP 驱动签名/安全软件拦截 | 白名单引导 + 数字签名；Wintun 备选 |
| 特定 Windows 版本驱动兼容（蓝屏） | Wintun 作为默认备选路径 |
| 无管理员权限 | 用户态代理模式自动降级 |
| 虚拟 IP 冲突 | room_id 哈希派生 + 冲突检测 + 自动重分配 |
