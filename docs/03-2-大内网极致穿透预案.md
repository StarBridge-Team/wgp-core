# 大内网极致穿透预案

**状态**：V2 规划（2026-09-06 范围调整：扩散穿透不进入 v1 内核，本预案保留为 V2 设计输入）
**关联算法**：时间戳协调 (§3.3) + 步长学习 (§3.4) + 三波探测 (§3.5) + 双模定时器 (§3.3.5)
**版本**：v0.1

***

## 一、问题定义

### 1.1 大内网的现实

```
典型的大内网拓扑:

  你的电脑 (192.168.x.x)
    ↓ NAT 层1: 家用路由器 (运营商分配的 10.x.x.x)
    ↓ NAT 层2: 小区/楼宇汇聚交换机 (运营商内网 100.64.x.x)
    ↓ NAT 层3: 运营商 CGNAT 网关 (公网 IP)
    ↓ 互联网
    ↓ 对端

  每一层 NAT 都在做端口映射转换 (NAPT)。
  要想直连对端，三层 NAT 的端口都必须猜对。
```

市面上的方案遇到多层大内网时，绝大多数选择走中继兜底。不是他们技术上行不通，而是**成本和回报不成正比**——为小概率场景投入大量工程资源，不如直接中继省事。部分开源方案（如 EasyTier）尝试了端口预测/生日攻击，但在三层 NAT 叠加下的成功率仍然不理想。

折跃门没有中继这张牌可以打，所以必须把这个场景啃下来。

### 1.2 为什么传统方案在这里失效

传统打洞只考虑单层 NAT：

```
传统打洞模型:
  端A (公网:portA) ←→ 端B (公网:portB)
  
  如果在 CGNAT 后面:
  端A (10.x.x.x:portA1) → NAT1 → NAT2 → NAT3 → (公网:portA4)
  
  三层映射: portA1 → portA2 → portA3 → portA4
  对端 B 需要猜的端口: portA4 (公网出口)
  
  三层映射 + 各自步长 → 公网端口变化规律被三层 NAT 叠加掩盖
  纯靠盲猜的成功率: 1% - 5%
```

## 二、算法核心：扩散穿透

### 2.1 核心思想

**不一次穿透三层，而是一层一层击穿。**

```
扩散穿透模型:

  第一波 (穿透 NAT1):  
    向家用路由器预测端口发包
    命中 → 获得家用路由器的公网侧映射端口 P1

  第二波 (穿透 NAT2):
    从 P1 端口位置扩散，向小区汇聚交换机预测端口发包
    命中 → 获得汇聚交换机的公网侧映射端口 P2

  第三波 (穿透 NAT3):
    从 P2 端口位置扩散，向运营商 CGNAT 预测端口发包
    命中 → 获得公网侧映射端口 P3

  对端收到的源端口: P3
  对端向 P3 发包 → 沿原路逐层透传到达端A
```

每层成功的信息**缩小**下一层的搜索范围，而不是盲猜。

### 2.2 扩散包设计

```
扩散探测包格式:

  ┌────────┬──────┬──────┬────────┬────────┬────────┬────────┬────────┐
  │  Magic  │Depth │ Layer│ PeerID │PrevPort│  Nonce │  TS    │ Payload│
  │  (2B)   │ (1B) │ (1B) │  (4B)  │  (2B)  │  (4B)  │  (8B)  │  (N-B) │
  └────────┴──────┴──────┴────────┴────────┴────────┴────────┴────────┘

  Magic:     0x5747 (Wormhole Protocol 魔数)
  Depth:     当前穿透路径总层数（通过 traceroute 预先探测）
  Layer:     当前是第几层 (1/2/3/...)
  PeerID:    对端身份标识
  PrevPort:  上一层穿透成功后映射的端口号（用于缩小本层搜索范围）
  Nonce:     随机值，用于区分不同探测包
  TS:        纳秒时间戳，用于时间戳协调对齐发包时机
```

### 2.3 层数探测（预测绘）

打洞开始前，先探测端到端路径上有几层 NAT：

```
LayerProbe 包:
  ┌────────┬──────┬────────┬────────┐
  │  Magic  │ Type │   TTL   │  Nonce  │
  │  (2B)   │ (1B) │  (1B)   │  (4B)   │
  └────────┴──────┴────────┴────────┘

  原理:
    发 TTL=1 的 LayerProbe → 第一跳回复
    发 TTL=2 的 LayerProbe → 第二跳回复
    发 TTL=3 的 LayerProbe → 第三跳回复
    ...

    根据回复的源 IP 判断:
      - 私有 IP (192.168.x.x / 10.x.x.x / 172.16-31.x.x) → NAT 层
      - CGNAT 预留 (100.64.x.x) → CGNAT 层
      - 公网 IP → 出口层

    最大探测深度: 4 层（超出则放弃扩散，回退标准三波）
```

**注意事项**：

- 部分路由器/防火墙会丢弃 TTL 超时的包，导致层数探测不准
- 探测不准时，默认假设 3 层（最坏情况），扩散完成后额外补一波兜底
- LayerProbe 结果缓存在本地，下次同网络环境直接复用

**时序与预算说明（重要）**：

- LayerProbe 逐跳 TTL 探测每跳通常需 1-5s（ICMP 超时），4 层探测合计 4-20s
- 此 4-20s **不计入下方 1.5s 打洞时间预算**，LayerProbe 应作为**后台异步预探测**
- 首次连接时 LayerProbe 在打洞前完成（增加首次连接延迟），后续复用缓存
- 缓存有效期建议 5 分钟（网络拓扑变化后失效）
- 1.5s 时间预算仅覆盖"扩散打洞本身"（三波发包+接收），不含 LayerProbe

## 三、与现有算法的结合

### 3.1 三层扩散的包数分配

```
打洞预算 (单侧总包数 ≤ 47):

  第一波 (穿透 NAT1):
    Depth ≥ 1
    向第一层 NAT 的预测端口窗口发 15 包
    命中率: ~60-80% (基于步长学习 + 时间戳)
    等待 400ms

  第二波 (穿透 NAT2):
    Depth ≥ 2, 且第一波成功
    从第一波获得的 P1 端口扩散，发 15 包
    预测窗口基于: P1 + NAT2 步长模型
    命中率: ~50-70%
    等待 500ms

  第三波 (穿透 NAT3):
    Depth ≥ 3, 且第二波成功
    从第二波获得的 P2 端口扩散，发 11 包
    预测窗口基于: P2 + NAT3 步长模型
    命中率: ~30-50%（对齐 03 §3.1 NAT4 目标口径）
    等待 600ms

  三层都成功: 双向穿透完成
  某层失败:  回退到从该层之后的盲猜撒网

  单侧总包数: 15 + 15 + 11 = 41 包 (约 2.6 KB；≤47 预算含回退撒网余量)
  总耗时:     400ms + 500ms + 600ms = 1.5s (含层间等待)
```

### 3.2 步长学习（已有 §§3.4）

**每层独立进行步长学习**。原理同 §3.4，但改为每层各做 3 次探测：

```
层1 步长学习: 家用路由器层
  发 STUN 到公网服务器 → 记录家用路由器映射端口变化
  3 次 → 学会层1 的步长模式

层2 步长学习: 汇聚交换机层
  难度较高（层1 的映射会遮蔽层2 的行为）
  替代方案: 通过信令服务器通告"我的层2 NAT 可能是 X 厂商设备"
  如果同运营商，层1 ~ 层2 的步长模式可能相似（同一硬件厂商）

层3 步长学习: 运营商 CGNAT 层
  通过标准 STUN 学会层3 步长模式 (已有 §3.4 实测数据)
  电信 NAT4: 区内步长 2-12
  移动 NAT4: 区内步长 3-14 (注意子跳变)
```

### 3.3 时间戳协调（复用 03 文档 §3.3）

每一层扩散波次都使用时间戳协调对齐发包时机：

```
时间戳协调流程 (每层独立):

  Alice 发第一波 → 信令通知 Bob "我在 T1 发层1 扩散包"
  Bob 在 T1 + RTT/2 同时发层1 扩散包

  层1 成功后:
  Alice 通知 Bob "层1 成功, P1=xxxx"
  Bob 根据 Alice 的 P1 调整层2 预测窗口

  层2 同时发包:
  Alice 在 T2 发层2 扩散包 (基于 P1)
  Bob 在 T2 + RTT/2 发层2 扩散包 (基于 Alice 通告的 P1)
```

### 3.4 三波回退融合

```
如果扩散穿透失败 → 回退到标准三波探测 (§3.5):

  标准三波探测 (盲猜公网端口):
    第一波: 21 包 (±50 预测窗口)
    第二波: 15 包 (±回退捕获)
    第三波: 11 包 (±3000 大撒网)

    总包数: 47 包, 耗时 ~1.5s

  这样既没有增加任何额外开销——扩散打到哪层算哪层，
  打不通自动回退盲猜。单轮总包数永远不会超过 47 包 (3KB)；
  叠加重试链时受会话总预算 ≤500 包/10 分钟约束。
```

## 四、扩散穿透策略

### 4.1 核心原理

扩散穿透通过逐层击穿 + 层级间信息传递，将多层 NAT 的搜索空间从"指数级盲猜"缩小为"逐层缩窄"。每层穿透成功后，用获得的端口信息缩小下一层的搜索范围。

### 4.2 与盲猜对比

三层盲猜（无扩散）：每层独立盲猜，全通概率极低。
扩散穿透：逐层缩窄，每层穿透成功后将信息传递给下一层，大幅缩小搜索空间。

### 4.3 失败处理

失败层回退到撒网兜底模式，利用剩余包预算覆盖，不额外发包。

## 五、未解决的问题

| 问题            | 影响            | 待验证方式                     |
| ------------- | ------------- | ------------------------- |
| 层数探测不准确       | 扩散深度设错，浪费包数   | 实测不同网络环境 (校园网/企业网/家宽多层)   |
| 中间层 NAT 不回包   | 无法获取 P1/P2 端口 | 验证商用路由器/交换机对自定义 UDP 的转发行为 |
| 层间步长独立性       | 层1 映射会遮蔽层2 步长 | 在真实多层 NAT 环境下做步长学习测试      |
| 回退时机选择        | 等太久 vs 等不够    | 实测确定每层最佳等待超时              |
| 家用路由器老化       | 老旧路由器转发性能差    | 在多种型号路由器上测试               |
| 运营商 CGNAT 层深度 | 不同运营商层数不同     | 收集更多运营商层数数据 (移动家宽)        |

## 六、实现建议

### 6.1 分阶段落地

```
Phase 1: 标准单层打洞 → 已有 (§3.5 三波探测)
Phase 2: 层数探测 (LayerProbe) → 这个预案的入口
Phase 3: 双层扩散 (家用路由器 + CGNAT) → 最常见的大内网场景
Phase 4: 三层扩散 (家用路由器 + 汇聚 + CGNAT) → 最复杂场景
Phase 5: 自动切换扩散 vs 盲猜 → 根据 LayerProbe 结果决策
```

### 6.2 开关控制

```
配置项:
  enable_diffusion: bool    = true    # 是否启用扩散穿透
  max_diffusion_depth: u8   = 3       # 最大扩散层数 (1-4)
  diffusion_fallback: bool   = true    # 扩散失败是否回退盲猜
  layer_probe_timeout: ms   = 2000    # 层数探测超时
```

### 6.3 与 DSTE 的关系

扩散穿透解决的是 **NAT 穿透层**的问题。DSTE（见 06-双栈隧道编码整合算法）解决的是 **协议翻译**的问题。两者是正交关系：

```
连接建立流程:

  LayerProbe 层数探测
    ↓
  扩散穿透 (穿透三层 NAT)
    ↓ 成功
  如果双栈不兼容 → DSTE 协议翻译隧道
    ↓
  P2P 连接建立
    ↓
  心跳保活
```

扩散穿透和 DSTE 不会同时被触发——扩散穿透通了，DSTE 就不需要介入。

## 七、结论

这个预案的定位不是"已实现的特性"，而是"如果折跃门要攻克大内网场景，这是我们知道该怎么做的东西"。

它的核心逻辑很简单：**不要一次猜三层，猜完一层用结果缩小下一层的搜索范围。** 这个直觉是朴素的，但它把三层盲猜的三万分之一概率，变成了每层 50-80% 的条件概率。

需要验证的瓶颈不在算法设计，在**层间隔离**——家用路由器是否会把下一层探测包的反馈传回来。这不影响预案的正确性，只影响落地的顺序。

### 8.1 竞品效率推演（三层大内网盲猜）

```
每层 NAT 端口猜测假设:
  家用路由器:  端口范围 1024-65535，5% 概率命中（盲猜）
  汇聚交换机: 同上，5%
  运营商 CGNAT: 同上，5%

三层命中概率: 0.05 × 0.05 × 0.05 = 0.0125%
  → 八千分之一 ≈ 近乎不可能
  → 即使步长预测提升到每层 30%（估算的高值）
  → 三层: 0.3³ = 2.7%

这就是竞品全部选择中继兜底的原因——与其把钱砸在不知道能不能穿过去的算法上，
不如直接搭中继服务器，100% 解决问题。
```

### 8.2 折跃门的差异化维度

| 维度       | 竞品做法                   | 折跃门做法                             |
| -------- | ---------------------- | --------------------------------- |
| **中继依赖** | 有（高枕无忧，不逼自己）           | **无（倒逼极致优化）**                     |
| **端口预测** | 盲猜/生日攻击（单层预测）          | 步长学习 + 每层独立建模                     |
| **穿透策略** | 只看公网端口，一次性猜            | **扩散穿透**：逐层击穿，每层结果缩窄下一层范围         |
| **时序控制** | 标准 ICE 时序 (\~500ms 窗口) | 时间戳协调 + 双模定时器 (±1ms 级精度, 150ms 窗口) |
| **带宽控制** | 无专门优化                  | ≤47 包 / 3KB                       |
| **层数感知** | 无（不知道有几层 NAT）          | LayerProbe 预先探测层数                 |
| **实测数据** | 无专门收集                  | 7 份实测报告（电信 NAT3/NAT4 + 移动 NAT3/NAT4）   |

### 8.3 为什么折跃门必须做这件事

折跃门承诺了**无中继**——不做中继所以必须在竞品投降的战场上赢。扩散穿透是唯一途径。
