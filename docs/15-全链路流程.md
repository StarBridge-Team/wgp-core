# 15-全链路流程（端到端）

**状态**：v1.0（2026-09-10）
**定位**：从开机到业务跑通的完整流程权威版。时序、包数、并发关系以此为准；与 00 §4 状态机、07 信令面、14 API 相互印证。

---

## Phase 0 常驻预探测（缓存 5 分钟，网络切换即失效）

```
① 时间锚点   NTP/淘宝 HTTP → 长沙 Date 头兜底（net_time_anchor，仅 Instant 换算）
② NAT 判定   向两个不同 IP 观察者发 STUN binding（长沙 + 一公共 STUN）
③ 出站预判   UDP 可用性 + ICMP 可用性 + LAN 组播 beacon 监听启动
④ 模型缓存   步长模型/路由表/种子缓存直接复用（过期才重学）
```

## Phase 1 建房（Alice）

```
派生 U/ 码(13 算法) → DHT 写房间键{成员=[Alice],锚点=Alice,epoch=0,房主签名}
→ 30s 租约续期循环启动 → LAN 组播 beacon 开始广播
→ 房码经口头/IM 给 Bob（不走网络）
```

## Phase 2 加入（Bob）

```
U/ 码+房间密钥 → DHT 查键(room_key=SHA256("wgp/room/v1"||房码))
→ 读锚点 → 向 Alice 报道 → Alice 更新成员表(签名, epoch 不变)
→ Bob 与 Alice 进入结对流程
```

## Phase 3-8 每对 Peer 打洞会话（核心）

### Phase 3 承诺-揭示（约 3 RTT，经任意 DHT 转发者，长沙兜底）

```
各生成临时 X25519 密钥对+32B nonce → commit=SHA256(Pub||nonce) 互发(3s 超时不降级)
→ 互相揭示验证，不匹配=断连+24h 黑名单
→ shared → HKDF → session_key / PSK identity / punch_key / hb_key
→ 能力位交换：UDP 可用、transport 能力集、AppType 三档、crypto_profile
```

### Phase 4 观察与测量（与 Phase 3 并行，约 600ms）

```
双方各向 K=2 观察者(长沙+公共 STUN)发扩展 Binding → 获"我的公网端点"报告 ×2
→ 经 DHT 交换双方报告 → 交叉比对(取多数)
→ 步长学习: 同目标 STUN 连发 3 次 → PortStepModel（缓存命中跳过）
→ 时间对齐: 交换 net_offset 算 delta → 协商 T_offset 相对偏移（禁 SystemTime）
```

### Phase 5 竞速打洞（调度器统一发包，H6 预算闸门）

```
路径① LAN 组播: beacon 互见 → 直连判定，命中则跳过②③
路径② UDP 三波(主): 双模定时器对齐 T_send 同步发包
    第一波 21 包预测窗口 → 800ms → 第二波 15 包回退 → 800ms
    → 第三波 11-36 包撒网(低置信度开)
    辅助: ICMP 反推收 unreachable 实时缩窗口(0 包成本)
路径③ TCP simultaneous open（T1-T4 任一触发）:
    T1 预判 UDP 不可达 / T2 三波全灭 / T3 QUIC 握手超时 3s / T4 运营商画像差+对端同意
预算: 单侧 ≤47 探针/轮；会话 ≤500 包/10min
```

### Phase 6 验证与握手（先通先用）

```
验证: 收对端探针且 punch_key HMAC 过 → 才算打通（防伪造）
UDP 通 → yield PunchedLink(Udp) → 同 socket 双向 QUIC 握手(TLS-PSK, 3s 超时)
   ├─ 成功 → Connected(主档) ✓
   └─ 超时(疑 DPI) → 触发路径③
TCP 通 → PunchedLink(Tcp) → TLS-PSK+帧流 → Connected(降级档)
全灭 → ICMP identifier 打洞 → 逃生档(仅信令级)
   └─ 仍不通 → 死局评分(04 D5)≥70 → 诊断报告告知用户，不再空转
```

### Phase 7 稳态保活（内核唯一负责，外围零心跳）

```
动态心跳 500ms-15s，NAT 超时学习调优；每 10 次带 1 次步长校准扩展
端口监控: PortShifted 更新预测 / NetworkChanged 重启流程
降级档每 30s 探 UDP → 恢复则重打洞 → upgraded(新链路) → 旧链路宽限 30s
NAT 重绑定 → QUIC 连接迁移吸收；迁移失败 → 内核重打洞(lost → yield 新链路)
```

### Phase 8 清理

```
离开: 成员表除名、停租约、密钥全 zeroize、socket/预算归还
房主离开: 租约 75s 超时 → 继位链首位 CAS 抢占 → epoch+1 → 新锚点续租约
```

## 多人增量（Carol 加入 Alice+Bobby 的房间）

```
Carol Phase 2 报道锚点 Alice → Alice 通报 Bob 与 Carol 互打
→ Bob↔Carol 走完整 Phase 3-7（mesh 增边）
→ 密钥逐对独立、会话逐对独立、保活逐对独立；锚点全程只协调不碰业务流
```

## 资源账本

| 路径 | 典型耗时 | 包成本 |
|------|---------|--------|
| LAN 组播命中 | <1s | ≈0 |
| UDP 高置信命中 | ~650ms + QUIC 握手 | ≤21 探针 + STUN 3 + 信令 |
| UDP 全灭→TCP | 3-6s | ≤47 + TCP 握手 |
| ICMP 逃生 | +2-4s | 极小（限速帧） |
| 死局判定 | 10-15s 必出报告 | — |

**总原则**：Phase 6 打通后，数据面全走 QUIC/TLS-PSK，此后内核与第三方（DHT/观察者/STUN）在业务存续期零交互——洞打好，内核退居幕后，只留保活哨兵。
