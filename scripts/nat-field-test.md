## 0. 准备一台公网种子

要求很低：1 核 / 512MB、公网 IPv4、放行 **UDP 11010**、**UDP 3478**、**TCP 3481**（云厂商安全组 + 本机防火墙都要放）。

```bash
# 用发版包里的静态二进制，或本机交叉编译（见 .github/workflows/release.yml 的 musl 目标）
scp wgp-node root@<seed>:/usr/local/bin/
ssh root@<seed>
wgp-node --bind 0.0.0.0:11010 --advertise <seed 的公网 IPv4> \
         --identity /var/lib/wgp/node.key --log-level info
```

启动后确认三件事：

1. 日志里出现监听端口与「宣告」提示；
2. 从任一台客户端 `wgp-client ... -p udp://<seed>:11010` 能测速成功（打印往返耗时）；
3. `--advertise` 的 IP 就是客户端能连到的那个公网 IP（不要在 NAT 后）。

## 1. 两台异 NAT 客户端

| 端 | 建议环境 | 理由 |
|---|---|---|
| A | 家宽 / 手机热点（CGNAT） | 验证 CGNAT 下无法端口映射时的降级行为 |
| B | 另一个运营商或云主机（公网 IP） | 与 A 的 NAT 行为不同，才算「异 NAT」 |

两端都用**同一份发版包**，各自独立身份文件：

```bash
# A（房主，暴露游戏端口）
wgp-client 开房 -n field-test -k <口令> -p udp://<seed>:11010 --expose 25565 -i a.key

# B（加入方）
wgp-client join -n field-test -k <口令> -p udp://<seed>:11010 --forward 25565 -i b.key
```

## 2. 要记录什么（与 18 §7 表格一一对应）

- **入网时间**：从进程启动到打印「已入表」的秒数。
- **探测结果**：NAT 类型、观察者数量与往返、三波命中波次。
- **丢包**：隧道起来后跑一次 `iperf3` 或包内 `echo_tool`，记录吞吐与重传/丢包计数。
- **失败阶段**：入表 / 选点 / 协商 / 打洞 / 握手，哪一步先超时。
- **CGNAT 判定**：A 端若在 CGNAT 后，**不得**把自己宣告成可公网直连；日志里应能看出「只作为成员」。

## 3. 必做的三个变体

1. **正常路径**：A 与 B 都走 UDP 种子，验证打洞与转发。
2. **UDP 被封**：两端都改用 `-p tcp://<seed>:3481`。
   期望：入表、选点、房间读写成功（TCP 信令），但打洞失败并给出「打洞与数据面仍需要 UDP」的说明。
3. **旧节点兼容**：拿一个 11-15 之前的 `wgp-node` 当种子，客户端默认严格模式应报「对端不支持身份证明」；
   两端加 `--allow-legacy-identity` 后应恢复旧行为。这条用来验证升级策略不是纸面承诺。
