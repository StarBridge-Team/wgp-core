# 折跃门 wgp · 预览构建

纯 P2P 打洞联机：两端直连传数据，第三方（种子节点）只帮忙牵线，不转发业务数据。

> **状态**：回环（loopback）上全流程验证通过；**尚未做过真机、真实 NAT 下的双端联调**。
> 请当作预览版试用，打不通时把两端的终端输出留下来。
> 本包的版本、提交号见 `BUILD-INFO.txt`，文件校验值见 `SHA256SUMS.txt`。

## 包里有什么

| 文件 | 用途 |
|---|---|
| `wgp-client` | 客户端：开房 / 加入 / 端口转发 |
| `wgp-agent` | 客户端 agent（多进程阶段 1）：持有身份与 socket，经**仅本机** IPC 接受控制 |
| `wgp-node` | 种子节点（公网固定地址；允许信令中转） |
| `wgp-node-hobby` | 贡献节点（家庭宽带；拒绝信令中转） |

Windows 包里这四个文件带 `.exe` 后缀；Linux 包是 musl 静态链接，解压即用。

`wgp-agent` 目前还没有 GUI 前端，用 `wgp-agent ping` 自检、`wgp-agent --help` 看用法；
它的 IPC 端点只在本机（Unix socket 0600 / Windows 命名管道仅属主），详见
[`client/wgp-agent/README.md`](https://github.com/StarBridge-Team/wgp-core/blob/main/client/wgp-agent/README.md)。

## 三步联机（以 Minecraft Java 版 25565 为例）

**1. 一台公网机器跑种子**（放行 UDP 11010、UDP 3478、TCP 3481）：

```
wgp-node --bind 0.0.0.0:11010 --advertise <本机公网IPv4>
```

`--advertise` 让种子对外宣告自己，客户端据此自动找到观察者。有多个种子时，用
`--peers udp://<另一个种子>:11010` 让它们互相认识。

**2. 房主**（游戏服务器所在的机器）：

```
wgp-client 开房 --name 我的房间 --key 一个口令 -p udp://<种子地址>:11010 --expose 25565
```

**3. 朋友**：

```
wgp-client join --name 我的房间 --key 一个口令 -p udp://<种子地址>:11010 --forward 25565
```

看到 `[隧道] 就绪` 之后，游戏里连 `localhost:25565`。

- **最省事的办法**：房主启动后会打印一行完整的加入命令（`wgp-client join U/xxxx-… -p … --forward …`），
  把这一行发给朋友，对方原样执行即可，不用再核对房间名、口令、种子和端口。
- 自己敲命令的话，双方的房间名和口令必须一致。
- 加入时如果看到「没有找到这个房间」，说明此刻房间里只有你自己：核对房间码，确认房主已经在线。
- 命令 `开房` 也可以写成 `host`。
- 种子**没有**用 `--advertise` 宣告自己时，两端都要加 `--observer <种子IP>:3478`（要填 IP，不支持域名）；
  否则不做 NAT 探测，只能走 TCP 兜底，成功率会明显下降。
- 两个人填的种子不必相同，只要这些种子互相认识。
- 退出按 Ctrl+C。

## 端口转发规则

| 选项 | 含义 |
|---|---|
| `--expose 25565` | 把本机 `127.0.0.1:25565` 暴露给房间成员 |
| `--expose 25565=192.168.1.20:25565` | 暴露局域网里另一台机器上的服务 |
| `--forward 25565` | 本地监听 `127.0.0.1:25565`，转发到对端暴露的 25565 |
| `--forward 30000:25565` | 本地改用 30000 端口 |
| `--forward 0.0.0.0:25565:25565` | 对局域网开放（默认只监听本机） |
| `--expose-udp` / `--forward-udp` | 同上，走 UDP（基岩版 19132 等） |

选项可以重复给出，也可以用逗号分隔多条规则。对端只能连到明确 `--expose` 的端口。

## 已知限制

- **种子里至少要有一个 `wgp-node`（完整版）**。只有 `wgp-node-hobby` 时，第二个成员无法入表：
  报道与密钥协商都要经种子中转信令，而贡献节点拒绝一切中转。贡献节点和完整版种子搭配使用没有问题。
- 本版与更早的构建不能混用：加入房间的报文格式改过，探活也改成了签名的挑战响应。旧节点不会被采信
  （严格模式），需要临时兼容时给两端都加 `--allow-legacy-identity`。
- UDP 被封锁时：用 `-p tcp://<种子>:3481` 可以让**入表、选点与房间读写**走 TCP 信令；但打洞与业务数据
  仍然需要 UDP，两端之间 UDP 完全不通时隧道建不起来（命令会给出明确提示）。
- 身份文件（客户端 `wgp-client.key`、agent `wgp-agent.key`、节点 `node_identity.key`）生成在启动目录，
  删掉就是换了一个新身份。
