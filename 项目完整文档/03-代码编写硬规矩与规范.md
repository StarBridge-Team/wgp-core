# 03 · 代码编写硬规矩与规范

> - 来源：`docs/00` §1/§3/§4/§8、`docs/14`、`docs/16` §6、`docs/01`，以及对全部 57 个源文件风格的实地提炼（经 grep 核实）
> - 生成日期：2026-11-05
> - 用途：动手写代码**之前**读本文；红线是**默认纪律**（变通需按 §1 登记理由），风格约定与现有代码保持一致。

---

## 1. 总纲：代码即契约，但契约服从现实

- **权威顺序：代码现状 > 设计文档 > 硬约束 > 个人偏好。** 代码是最终权威——设计文档与硬约束描述的是"某个阶段的意图"；当意图与现实冲突时，**改文档/约束去匹配代码，而不是把代码掰弯去迁就旧文档**。
- **需求可以灵活改变**：硬约束（00 §1 H1–H6）与设计文档不是教条，是当前阶段的默认纪律。当实测数据、新需求、更优解法出现时，允许修订约束与文档——但必须走**变更记录**（在 14 §12 或本文件登记"改了什么、为什么、影响面"），不允许无声突破，也不允许拿"灵活"当绕过评审的借口。
- **漂移是信号，不是错误**：14 文档原定位"实现与文档漂移即 bug"；按现行权威顺序，漂移首先意味着**文档待更新**——把差异回写 14 §12 实现演进记录表（现已有 12 条）或对应设计文档，保持文档与代码同步。
- 注释与代码不一致时以代码为准，并在文档/注释中标注"代码如此，意图待确认"（本次完整文档已登记多处，如 `CommitBody` 注释 33B 实际 48B）。

## 2. 七条代码硬规矩（默认红线，变通需登记）

> 红线是**默认状态**而非铁律：确需变通时，按 §1 变更记录流程登记理由（改了什么/为什么/影响面），评审后生效；**无声突破 = 缺陷**。

| # | 规矩 | 代码级落点 | 自查方法 |
|---|---|---|---|
| R1 | **内核不碰业务数据**（H1/H4）：不建 QUIC 连接、不解析应用协议、不做流控重传、不做应用适配、不碰房间业务数据 | wgp-core 只产 `PunchedLink` 与事件；socket/密钥交付即归外围 | 新增任何"数据面"逻辑前先确认它属于外围任务 |
| R2 | **禁止读取系统时间**（H5） | 全内核 `SystemTime` 出现次数 = **0**（已 grep 核实）；时间协调只用 `Instant` + 网络锚点（03 §3.3） | `grep -r "SystemTime" kernel/` 必须零命中 |
| R3 | **调度器是唯一发包点**（H6） | 所有探针/保活包必须经 `BudgetScheduler::try_acquire(1)` 扣减（≤47 包/轮、≤500 包/10min）；任何模块私自发探测包 = 缺陷 | 新增发包路径必须看到预算闸门调用 |
| R4 | **密钥只经 `SecretBox` / `PunchedLink` 流转，全生命周期 zeroize** | `SecretBox::take` 取出即销毁 + `Drop` 兜底；`take_tls_psk` 一次性；内核任何路径不得缓存明文副本（14 §10 条款 3，zeroize 审计点） | 新密钥变量必须进 zeroize 清单（01 §1.4.2 第 9 条） |
| R5 | **proto/crypto 零 IO、零 async、零 tokio；proto 零第三方依赖** | wgp-proto `[dependencies]` 为空；crypto 仅密码学 crate；手写定长编码，禁 serde/protobuf | `cargo tree -p wgp-proto` 应无节点 |
| R6 | **依赖白名单制**（00 §8） | L1 硬许可（tokio/socket2/x25519-dalek/ed25519-dalek/sha2/hkdf/hmac/aes-gcm/zeroize/bytes/rand_core，均经审计）；**禁止** libp2p（身份体系冲突）、serde/protobuf（定长手写编码）、现成 STUN/NTP 库（自研）、任何 P2P 全家桶；quinn/rustls 属客户端数据面，内核不引入 | 加依赖前先查 00 §8 分级表 |
| R7 | **身份与端点保密** | 服务器 IP 不进代码注释/文档/公告/群消息，只进客户端种子列表（00 D12）；身份文件 32B 长度校验，长度非法**拒绝启动**，宁可人工确认也不静默换身份（07 §8：身份漂移 = DHT 键散乱 + 日蚀风险） | 提交前全局搜 IP/域名 |

## 3. 新增与修改代码的流程规矩

1. **先查代码现状，再查文档**：涉及打洞看 03/04，信令看 07，接口看 14，时序看 15；但最终以**代码现状**为准。文档没覆盖的新功能，按 §4 风格约定与 §2 红线实现，完成后回写文档（03/14/15 对应章节）。
2. **扩展走预留接口，不改引擎**：
   - 新传输载体 = 新写一个 `ProbeCarrier` 实现（引擎零改动，14 §11）；
   - 新密码学 = 新写一个 `KeyAgreement` 实现（调用方零改动，PQ 开启点：`algo_id=0x02` + 协议版本号递增）；
   - 新协议字段 = wgp-proto 加定长编解码 + 版本/能力协商位，**不得**就地改已有字段语义。
3. **漂移回写文档**：签名/行为与 14 文档不一致时，以代码现状为准，把差异回写进 14 §12 表（条款/文档初版/实现定版/原因四列）或修订对应设计文档——**代码先行，文档跟上**。
4. **验证门**：改完必跑 `cargo test --workspace` 全绿；`cfg(unix)` 分支（ICMP ping-socket）以 Linux 真机 `cargo test` 为验证门（DEPLOY.md 第 0 步）；部署件改动先在 Linux 做 `bash -n` / `systemd-analyze verify`。
5. **提交前自查清单**（见 §7）：红线七条 + 测试 + 漂移登记 + IP 保密 + 身份文件未动。

## 4. 代码风格规范（现行约定，与源码一致）

### 4.1 文件与模块组织

- crate 一律 `wgp-*`；目录分层 `kernel/`（纯算法）→ `server/` → `client/`。
- **每个文件顶部写 `//!` 模块级 rustdoc**，注明定位并引用设计文档章节，现有代码全部如此。示例（wgp-punch/src/lib.rs）：

```rust
//! 折跃门打洞引擎（03/04 文档的代码化）。
//! 纪律（00 §3）：调度器是唯一发包点（H6）；内核只产链路、不跑数据。
```

- 一个文件一个职责；对外 API 经 `lib.rs` 的 `pub use` 门面化再导出（如 wgp-proto 只再导出 4 项门面级 API，其余走模块路径，避免 `classify`/`md5` 这类通用名冲突）。
- 依赖单向：`proto ← crypto ← punch ← dht ← core`，不允许反向依赖。

### 4.2 命名

| 对象 | 约定 | 示例 |
|---|---|---|
| 类型/函数/模块 | snake_case | `PortStepModel`、`plan_waves`、`derive_room_code` |
| 常量 | SCREAMING_SNAKE，集中在 `consts.rs` | `PROTO_VERSION`、`LEASE_INTERVAL_S`、`ROOM_KEY_DOMAIN` |
| 魔数/域分隔字符串 | 命名常量，禁裸字面量散落 | `SIG_MAGIC = [0x57,0x47]`("WG")、`b"wgp/room/v1"`、`b"zheyuemen/v1/ecdh-salt"` |
| 错误类型 | `XxxError`，优先携带 `&'static str` 或枚举 | `CarrierError(pub &'static str)`、`BudgetError`、`OrchestratorError`、`RoomError` |
| trait | 行为命名，方法最小化 | `ProbeCarrier`（4 方法）、`KeyAgreement`（4 方法） |

### 4.3 注释与文档

- **中文注释**；注释解释"为什么/设计依据"而非复述代码，引用设计文档章节号（`00 §3`、`03 §3.4`、`14 §10`）。
- 公开类型/函数必须写文档注释；**安全语义必须显式写明**（如 `SecretBox`："一次性取出；此后本容器归零"）。
- 已知不一致处按"代码如此，意图待确认"标注，不静默修改语义。

### 4.4 编码与解码（wgp-proto 层）

- 定长手写二进制编解码，**禁止 serde/protobuf/JSON**（R6）。
- 多字节整数一律**大端（BE）**；定长走 `&mut [u8; N]` 出参，变长走 `Vec<u8>`。
- **解码失败一律返回 `Option::None` / `Err`，绝不 panic**；超限输入严格拒绝。
- 已知的有意不对称：`encode` 对超限载荷静默截断、`decode` 严格拒绝（读写端语义，见 10 号文档 §6.4）——保持该模式，不要"修复"成对称。
- 字节布局改动必须同步更新 10 号文档与设计文档，并补/改测试向量。

### 4.5 错误处理

- **生产路径零 panic**：已核实 `panic!`/`todo!`/`unimplemented!` 仅出现在 `#[cfg(test)]` 测试模块；`unwrap()` 在生产代码中仅限两种场景——编译期常量（如 `"0.0.0.0:0".parse().unwrap()`）与已校验长度的切片转换（如 `d[0..8].try_into().unwrap()`）。其余一律 `?` / `map_err` 向上传播。
- **静默丢弃策略**：探针验签失败、重放窗口外、限频超限的包一律静默丢弃，不进入转发路径、不回错误包（缩小攻击面）。
- RPC 超时即失败返回，重发由上层自持（"上层信令自持超时重发"）；本层不做重试循环。

### 4.6 并发与 async

- tokio 异步只允许出现在 `wgp-dht`/`wgp-core`/`wgp-node`；`proto`/`crypto`/`punch` 保持纯同步（R5）。
- 载体接口：`send_probe` 为原生 `async fn`（快速路径复用调用方 executor），`on_probe` 同步（读循环单包即可判定）。
- 事件通道用 tokio `broadcast`；消费侧 `Lagged(n)` 时丢弃并告警，不补放。
- 保活、竞速、成员感知等长生命周期任务用 `spawn` + `Arc` 共享状态；取消语义：`JoinHandle::leave()` 后 100ms 内完成清理，无悬挂流量（14 §10 条款 6）。

### 4.7 安全编码

- 密钥材料全生命周期 `zeroize`：临时私钥、共享密钥、HKDF 中间态、会话密钥、NONCE_PREFIX、Counter（01 §1.4.2 第 9 条清单）。
- 公开 `enum` 一律 `#[non_exhaustive]`；trait 新增方法走默认实现或版本协商位（14 §11）。
- 认证最小化：探针 31B（含 12B 截断 HMAC）、心跳 19B/23B；AAD 能带尽带（逃生帧例外：当前无 AAD，属已知限制）。
- 承诺-揭示：commit 3s 超时**不降级**为无承诺模式；揭示验证失败 = 断连 + 24h 黑名单。

### 4.8 feature 与平台

- feature 门控做编译期裁剪：`client`（默认，全量）/ `node`（服务端四职，空 feature + `#[cfg(feature="client")]` 反向收敛）。新模块默认挂 `client`，服务端不需要的不得进 `node` 面。
- 平台差异用 `cfg(unix)` / `cfg(windows)` 隔离（ICMP：Windows iphlpapi / Unix ping-socket 双后端），不混平台代码；新平台分支必须能在交叉编译中通过。
- 零平台依赖代码 + tokio 抽象 = 跨平台性保证；不得引入 `winapi`/`libc` 直调（现有实现经 socket2/标准库）。

## 5. 测试规范

- 每个算法/编解码模块配 `#[cfg(test)]` 模块；测试代码中的 `panic!`/`unwrap` 不受 §4.5 限制。
- **测试向量对拍是硬传统**：
  - `room_code`：4 组标准向量（`U/C2G9-GYET-311W-R636` 等）+ 格式断言（`U/` + 4×4 + 末 2 位进制 ∈ [10,36]）+ 确定性 + 消歧补丁，与 Python 参考实现对拍；
  - `punycode`：6 组向量；`md5`：5 组 RFC 1321 向量；
  - `handshake_test`：承诺-揭示 + HKDF 派生契约对拍；
  - `net_test`：DHT 转发承诺-揭示的端到端测试。
- 现状与边界（诚实声明）：**92 个测试全部 Windows loopback**；跨平台性由"零平台依赖 + tokio 抽象"保证，Linux 侧以 DEPLOY.md 第 0 步真机 `cargo test` 为验证门。
- 新代码必须带测试；修 bug 必须带回归测试；测试向量变更视为协议变更，需同步文档。

## 6. 明确"不要做"清单

来自 00 §4 不做清单与 16 §6：

1. 不在内核里建 QUIC、解析应用协议、转发业务包（H1/H4）。
2. 不把服务器 IP 写进文档/公告/群消息（D12）。
3. 不同一台机器同时启 `wgp-node` 和 `wgp-node-hobby`（端口 11010/3478/3481 冲突）。
4. 不删 `node_identity.key` / `wgp-client.key`（身份漂移 = 新节点）。
5. 双端打洞账本通过之前，不开工 wgp-port / wgp-tap / QUIC 数据面。
6. 不引入重依赖：libp2p、serde/protobuf、现成 STUN/NTP 库、P2P 全家桶。
7. 不改"调度器唯一发包点"设计；不加绕过预算闸门的发包路径。
8. 不在没有设计文档依据的情况下新增协议字段或改字段语义。
9. 不用 `SystemTime`；不让外围自发心跳（保活唯一权在内核）。
10. 不并行铺摊子：按 16 §4 的下一步顺序单线推进。
