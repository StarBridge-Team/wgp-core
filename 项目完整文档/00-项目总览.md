## 1. 一句话定义

**折跃门是纯 P2P 零中继的 NAT 打洞组网工具**：两端业务数据端到端直连，第三方（种子节点、观察者、STUN）只承担信令与端点观测，**永不转发业务流量**。项目要解决的核心问题是：在没有中继服务器兜底的前提下，让位于各种 NAT（尤其是对称 NAT / 运营商级 CGNAT）之后的两台设备直接打通。

```
客户端 A ──打洞直连（业务流量，端到端加密）── 客户端 B
     \                                      /
      \                                    /
       种子节点 wgp-node（DHT 信令 + 观察者/STUN + TCP 信令兜底）
       （只传信令，不碰业务包）
```

## 3. 六条硬约束（任何设计不得违反，00 §1）

| 编号 | 约束 |
|---|---|
| H1 | **纯 P2P 零中继**：业务数据端到端直连，任何第三方（信令节点、观察者、STUN）不得转发业务流量 |
| H2 | **端到端加密**：X25519 ECDH（承诺-揭示）产会话密钥；数据面加密由 QUIC-TLS / TLS-PSK 承担；逃生通道沿用 AES-GCM 帧 |
| H3 | **零自建成本路线**：信令去中心化（自研 DHT），唯一现有基础设施 = 公网种子节点 + 公共 STUN 兜底，社区节点未来分担 |
| H4 | **内核只管打洞**：内核不解析应用协议、不做数据转发重传、不做应用适配 |
| H5 | **Rust 实现；禁止读取系统时间**（时间协调仅用 `Instant` + 网络锚点） |
| H6 | **发包速率自限**：会话总预算 ≤ 47 包/轮、≤ 500 包/10 分钟，调度器是唯一发包点 |

> 关键认知：无中继 ≠ 无第三方。打洞在数学上需要"观察者"报告双方公网端点，承诺-揭示需要"转发者"。H1–H2 保证这些第三方**不可信也能安全运行**。
>
> 灵活性说明：H1–H6 是当前阶段的**默认纪律**而非教条——实测数据或新需求出现时允许修订，变更须登记（权威顺序与变更流程见 `03-代码编写硬规矩与规范.md` §1）。

## 4. 整体架构（一张图）

```
┌────────────────────────────────────────────────────────────────────�
│ 外围（客户端任务，尚未产品化）                                        │
│   wgp-client（CLI 参考外围） → 未来：wgp-port 端口转发 / wgp-tap 虚拟网卡 │
│   QUIC 数据面（quinn+rustls，TLS-PSK）/ TLS-PSK+帧流 / ICMP 逃生        │
├────────────────────────────────────────────────────────────────────┤
│ 内核 kernel/（纯算法，H4：只管打洞）                                   │
│   wgp-core    门面 Engine：PunchedLink 交付物 + 保活唯一权 + 全部对外 API │
│   wgp-punch   打洞引擎：状态机 / 竞速调度器（唯一发包点）/ 步长学习 / 三波  │
│   wgp-dht     信令面：Kademlia 变种 / 房间键 / 租约继位 / 观察者协议       │
│   wgp-crypto  密码层：承诺-揭示 / HKDF / 探针 HMAC / 逃生 AEAD / PQ 可插拔 │
│   wgp-proto   协议层：包格式 / 常量 / 编解码 + STUN 最小子集（纯数据）      │
├────────────────────────────────────────────────────────────────────┤
│ 服务端 server/wgp-node：单进程四职                                     │
│   DHT 种子 / 观察者（STUN 扩展）/ STUN 响应器 / 承诺转发兜底              │
│   双形态：wgp-node（静态 IP 完整版）/ wgp-node-hobby（家宽贡献版，拒中转）  │
└────────────────────────────────────────────────────────────────────┘
依赖纪律（单向）：proto ← crypto ← punch ← dht ← core；proto/crypto 禁止依赖 tokio
```

链路优先级（竞速先通先用，降级档 30s 探测自动升级）：

```
LAN 组播 > QUIC（UDP 打洞） > TCP（TLS-PSK） > ICMP 逃生
```

## 6. 五分钟快速开始

```bat
:: 1) 编译 + 全测（Windows 开发机已通）
cd /d H:\mclink core
cargo test --workspace
cargo build --release
:: 产物：target/release/wgp-node.exe、wgp-node-hobby.exe、wgp-client.exe

:: 2) 起一台种子/观察者（默认即三端口规格）
target\release\wgp-node.exe --bind 0.0.0.0:11010 --stun 3478 --tcp 3481

:: 3) 两台机器联调（异 NAT，如家宽 × 手机热点）
:: 机器 A（房主）
target\release\wgp-client.exe 开房 --name 测试房 --key 自己设一个 ^
  --seed udp://轻松.躺进.icu:11010,tcp://轻松.躺进.icu:3481
:: 机器 B（贴入 A 打印的 U/ 码）
target\release\wgp-client.exe join U/xxxx-xxxx-xxxx-xxxx ^
  --seed udp://轻松.躺进.icu:11010,tcp://轻松.躺进.icu:3481
```

> 真打洞验证请带观察者：`--observer <种子公网IP>:3478`（缺省会跳过 NAT 探测、走 TCP 兜底）。
> 服务端部署（Linux systemd / nftables / Windows 一键包）见 `17-部署与运维.md`。

## 7. 胜算评估（00 §9，依据 nat/ 实测）

| 场景 | 胜算 |
|---|---|
| NAT1/2/3 | >95%（实测全顺序分配） |
| 电信类 NAT4×NAT4 | 40–70%（目标分区=唯一簇、簇内步长 2–12、同簇稳定 10/10） |
| 移动类 NAT4 | 20–40%（多簇+子跳变，窗口时效短） |
| 两层大内网 | 10–25%（扩散理论自洽，层间反馈未实测） |
| 三层大内网 | 5–15%（理论推演） |
| 死局叠加 | ≈0，快速告知（04 D5 止损设计） |
