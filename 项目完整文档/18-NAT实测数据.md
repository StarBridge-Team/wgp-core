## 2. 核心结论（报告的"第一性原理"）

1. **9 份实测，7 份运营商 NAT 为顺序分配，2 份境外 VPN 出口为不规则分配。无一出现真随机端口。**
2. 国内两大运营商 CGNAT 无论 NAT3 还是 NAT4，端口分配器均为 **"按目标分区 + 区内顺序推进"**——这是步长学习算法可行的根基。
3. **NAT4 ≠ 随机**：不同目标 IP 触发不同端口簇，但簇内仍然顺序分配（电信步长 2–12、移动 3–14），同目标连续请求端口稳定（10/10 全命中）。
4. 移动比电信多一层"子跳变"（+225~+474 创建新区间），子区间内仍是顺序小步。
5. 9 份样本 IPv6 均不可用——IPv6 直连暂不能作为国内环境的依赖路径。
6. Cloudflare STUN 在移动核心网（AS56040）与非宽带场景被拦截（error 10047），电信/移动宽带正常（80–100%）。

## 3. 分样本要点

- **样本 2（陕西电信）**：★ 极致可预测——94% 步长 ≤4，21 包可覆盖 23% 端口空间。预测窗口 ±50 的实证来源。
- **样本 4（河源电信 NAT4）**：主簇 30 端口步长 2–12 跨度 178；次簇（海外 STUN 触发）7 端口；簇间跳变 -4088。NAT4 行为模式的首次暴露。
- **样本 5（广州移动 NAT4 热点）**：每 STUN 目标一簇，模式"跳变 +235~241 → 区内小步 2–14 → 再跳变"；Cloudflare 10 轮全败（移动核心网拦截）。
- **样本 6（惠州电信非宽带）**：正负双向波动（-36~+61）且有端口复用（48474 出现两次）——Trend::Oscillating 的实证。
- **样本 7（龙川移动宽带）**：移动宽带同样单簇顺序，步长 2–13（80%）；各目标各有一次大幅跳变（-230/-112，疑端口池回绕）。
- **样本 8/9（VPN 出口）**：同为 Cloudflare AS13335，行为高度可复现——NAT3 + 不规则分配。推断为**共享端口池 + 多用户并发**（运营商 CGNAT 每用户独立端口段故有序；共享 VPN 出口多人交错故无序）。穿透策略：步长预测不可用 → ±3000 全量撒网 + ICMP 反推 + 47 包全给 VPN 出口层；失败回退 TCP/WSS 443 伪装。

## 4. 对端口预测的指导（→ 代码落点见 13 号文档）

| 学习结果 | 窗口宽度 | 适用场景 |
|---|---|---|
| 区内小步（±1~15） | ±50 | 陕西电信(1–4)、河源电信 NAT4(2–12)、广州移动(3–14)、龙川移动(2–13) |
| 区内中步（±16~320） | ±400 | 湖南电信(1–320)、四川电信(1–90) |
| 双向波动（-36~+61） | ±100 | 惠州非宽带 |
| 簇间跳变检测 | 当前簇 ±50 + 新簇撒网 | 移动热点频繁跳变 |
| 簇间大幅跳变（>2000） | ±3000 | 电信 NAT4 切换目标 IP |
| 不规则分配（1–812） | ±3000 兜底 | VPN 出口（样本 8+9） |
| 兜底（无数据/真随机） | ±3000 | 实测未出现，保留 |

**NAT4 特别处理**：双方互相通告"当前对目标用的端口簇 + 簇内步长模型"；打洞时对准同一目标簇发包；簇跳变后自动重新学习，不中断整体流程。

## 5. 与算法参数的对应

| 算法参数 | 实证依据 |
|---|---|
| 三波 21+15+11、800ms/波 | 03 §3.5；窗口 ±50/±400/±3000 即本报告 4.1 分层 |
| 置信度公式 1/(1+方差/100) | 步长越一致置信度越高（陕西 1–4 → 高置信） |
| 胜算评估表（00 §9） | NAT1/2/3 >95%；电信 NAT4×NAT4 40–70%；移动 NAT4 20–40% |
| ICMP 反推收 unreachable | VPN 出口等不可预测场景的关键依赖 |
| 扩散穿透（V2） | 两层/三层大内网 10–25% / 5–15%（理论推演，层间反馈未实测） |
