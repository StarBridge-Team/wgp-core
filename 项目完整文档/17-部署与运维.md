## 1. 部署形态总览

同一份代码、同一份配置，两个可执行形态：

| 形态 | 二进制 | 适用 | 中转能力 |
|---|---|---|---|
| **静态 IP 完整版** | `wgp-node` | 自有固定公网 IP 的服务器 | 启用全部职责（种子+观察者+STUN+承诺转发，允许 Forward） |
| **家庭宽带贡献版** | `wgp-node-hobby` | 社区贡献者家宽机器 | **强制拒绝 Forward 中转**（PCDN 自保），只承担种子+观察者+STUN+KV |

当前线上种子为贡献服务器：`udp://轻松.躺进.icu:11010` + `tcp://轻松.躺进.icu:3481`（IP 保密，只进客户端种子列表，不进文档/公告）。

**端口规划（07 §6 规格，二进制默认值）**：

| 端口 | 协议 | 用途 |
|---|---|---|
| 11010 | UDP | DHT 信令 |
| 3478 | UDP | STUN / 观察者 |
| 3481 | TCP | 信令兜底（UDP 被封时客户端由此接入，长度前缀帧） |

## 2. 配置文件与优先级

**优先级（四源合并，与 `server.rs::resolve_opts()` 同一套解析）**：

```
命令行 --flag  >  WGP_* 环境变量  >  wgp-node.conf（工作目录）  >  二进制内置默认值
```

**配置键全表**（`wgp-node.conf` 键名大小写不敏感，`-` 与 `_` 等价；环境变量加 `WGP_` 前缀）：

| 键 | 默认 | 说明 |
|---|---|---|
| `bind` / `WGP_BIND` | `0.0.0.0:11010` | DHT 信令 UDP 绑定地址（SocketAddr） |
| `stun` / `WGP_STUN` | `3478` | 观察者/STUN 端口，`none` 关闭 |
| `tcp` / `WGP_TCP` | `3481` | TCP 信令兜底端口，`none` 关闭 |
| `hobby` / `WGP_HOBBY` | `false`（贡献版恒 true） | 贡献模式：拒绝 Forward 中转 |
| `observer_rate_limit` / `WGP_OBSERVER_RATE_LIMIT` | `60` | 观察者每 IP 每窗口响应上限（2026-11-19 从 12 上调，见 §7） |
| `observer_rate_window` / `WGP_OBSERVER_RATE_WINDOW` | `10` | 限频窗口（秒） |
| `advertise` / `WGP_ADVERTISE` | 不宣告 | 对外地址：固定 IPv4 / **DDNS 域名** / `none` |
| `advertise_dht_port` / `WGP_ADVERTISE_DHT_PORT` | `0`（= 本机） | 对外 DHT UDP 端口（FRP / 端口映射） |
| `advertise_stun_port` / `WGP_ADVERTISE_STUN_PORT` | `0`（= 本机） | 对外 STUN 端口 |
| `advertise_tcp_port` / `WGP_ADVERTISE_TCP_PORT` | `0`（= 本机） | 对外 TCP 信令端口 |
| `ddns_refresh` / `WGP_DDNS_REFRESH` | `300` | DDNS 域名重解析周期（秒；0 = 只在启动时解析） |
| `allow_local_endpoints` / `WGP_ALLOW_LOCAL_ENDPOINTS` | `false` | 接受回环/私网端点（局域网或本机部署） |
| `identity` / `WGP_IDENTITY` | `node_identity.key`（工作目录） | 节点身份文件路径 |
| `log_level` / `WGP_LOG_LEVEL` | `info` | error/warn/info/debug |
| `config` / `WGP_CONFIG` | — | 显式指定配置文件路径 |

> 注意：旧纯位置参数（`wgp-node 0.0.0.0:11010 3478 3481`）仅首位 bind 向后兼容，stun/tcp 位置值已不生效（取默认 3478/3481）。

### 3.3 防火墙（nftables）

```bash
sudo apt install -y nftables
sudo nft -f server/deploy/wgp-node.nft   # [验证] nft list ruleset 显示 wgp 表
sudo systemctl enable --now nftables
```

`wgp-node.nft` 规则要点（源码逐行）：

```nft
flush ruleset                                    # 首行清空宿主机全部规则——脚本故意不代劳
table inet wgp {
    set protected_udp { type inet_service; elements = { 11010, 3478 } }
    set protected_tcp { type inet_service; elements = { 3481 } }
    chain input {
        type filter hook input priority filter; policy drop;
        iif "lo" accept
        ct state established,related accept
        ip protocol icmp drop                    # ICMP 全静默（减扫描发现面）
        ip6 nexthdr icmpv6 drop
        # 业务 UDP：单 IP 限速 40 包/10s（burst 20），超限 drop
        udp dport @protected_udp ct state new counter hashlimit \
            name wgp-udp above 40/10sec burst 20 packets drop
        udp dport @protected_udp accept
        # 信令 TCP：单 IP 新建限速 20/秒
        tcp dport @protected_tcp ct state new counter limit rate over 20/second drop
        tcp dport @protected_tcp accept
        counter drop                              # 其余全拒
    }
}
```

设计原则（注释原文）：协议本身是小包低频，正常流量远低于限速，**超频即视为滥用**。

### 3.4 服务安装（两种形态二选一，同一台机只启一个）

**静态 IP 完整版**：

```bash

sudo useradd -r -s /usr/sbin/nologin wgp 2>/dev/null || true
sudo cp server/deploy/wgp-node.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now wgp-node
```

**家庭宽带贡献版**（一键脚本）：

```bash

```

### 3.5 systemd 单元要点

| 项 | 值（两个单元一致） |
|---|---|
| WorkingDirectory | `/opt/wgp-node`（存放 node_identity.key） |
| ExecStart | 完整版：`/opt/wgp-node/wgp-node --bind 0.0.0.0:11010 --stun 3478 --tcp 3481`；贡献版：`/opt/wgp-node/wgp-node-hobby`（无参数，默认即规格） |
| EnvironmentFile | 贡献版：`-/etc/wgp-node/env`（前缀 `-` = 文件可不存在） |
| User/Group | `wgp`（无登录 shell） |
| Restart | `on-failure`，RestartSec=5 |
| MemoryMax | 256M（无状态服务，限一下防异常） |
| 加固 | NoNewPrivileges=true, ProtectSystem=full, ProtectHome=true |

### 3.6 install-hobby.sh 详解

```bash
# 可调安装位置（均有默认）：
WGP_INSTALL_DIR=/opt/wgp-node   # 安装目录
WGP_RUN_USER=wgp                # 运行用户
WGP_ENV_FILE=/etc/wgp-node/env  # 环境文件
WGP_BIN=.../target/release/wgp-node-hobby   # 二进制来源
```

脚本行为（`set -euo pipefail`）：① 校验 root 与二进制/单元/模板存在；② 创建系统用户；③ `install -m 0755` 装二进制；④ **环境文件已存在则绝不覆盖**（运维调过的配置是生产资产），仅首次从模板创建（`install -m 0640 -o root -g wgp`）；⑤ 装单元 + `enable --now` + 打印 status 前 12 行；⑥ 收尾提示防火墙/改参/看日志/自检命令。

## 4. Windows 一键部署包（hobby-windows/，免编译备用）

| 文件 | 说明 |
|---|---|
| `wgp-node-hobby.exe` | 贡献版二进制（release；内部恒定 hobby，`--no-hobby` 无效） |
| `wgp-node.conf` | 配置文件（启动自动加载；键与 `resolve_opts()` 对应） |
| `start-hobby.bat` | 启动脚本（`chcp 65001`、cd 到脚本目录、透传 `%*` 参数、退出打印码） |
| `firewall-hobby.bat` | 防火墙放行（**右键管理员运行**；端口从 conf 解析，与后端同源） |

**部署步骤**：① 管理员运行 `firewall-hobby.bat`（解析 conf 得 bind/stun/tcp 端口，`none` 则不放行；netsh 写入三条固定名规则 `wgp-node DHT (UDP)`/`STUN (UDP)`/`Signal (TCP)`，conf 改端口后重跑即原位更新）；② 光猫/路由器端口映射（UDP 11010/3478、TCP 3481 映射到本机内网 IP；桥接时只在路由器映射，光猫路由模式两层都映射）；③ 双击 `start-hobby.bat`，日志出现 `已就绪（种子+观察者+承诺兜底）` 即成功；④ 可选开机自启（`shell:startup` 放快捷方式）。

**验证**：日志出现 `node_id=xx:xx:xx:xx` 与三端口；外网用手机流量 `wgp-client --seed udp://你的公网IP:11010` 能 Ping 通即入网成功。

**卸载**：删目录 + 删防火墙规则（控制面板 → 高级设置 → 入站规则搜 "wgp-node"）。

> 每次重新 `cargo build --release` 后，把新的 `wgp-node-hobby.exe` 拷入本目录，保持包内二进制与源码一致。

## 5. 运维要点

- **升级** = `cargo build --release && cp` 覆盖二进制 + `systemctl restart`（无状态，无数据迁移）。
- **身份文件即服务器全部状态**：备份 `node_identity.key`；丢失 = 节点身份重生成（被已入网路由表视为新节点，无害但不优雅）。systemd 单元靠 `User=wgp` + 工作目录权限保证仅本服务可读。
- **改端口/限频**：编辑 `/etc/wgp-node/env`（去注释）→ `systemctl restart wgp-node-hobby`；不要写死在 unit 里。
- **被打（DDoS）预案**：架构级冗余兜底（社区种子顶替 / 公共 STUN 顶替观察者）；已建立 mesh 的业务流零影响——不需要为此买高防。
- **软件内置防护**（贡献模式三件事）：拒绝 Forward 中转（唯一可能产生持续流量的路径）；观察者限频 12 次/10s/IP；身份持久化。正常流量量级：一天信令总量低于几 MB；被运营商警告先查 hobby 没开。
- **家宽无固定公网 IPv4**：IP 变化后需更新客户端 `--seed`（DDNS 域名可缓解）；有公网 IPv6 时客户端可直连（防火墙规则放行 any profile）。

## 7. 部署拓扑：VPS / FRP 穿透 / NAPT 映射 / DDNS / 局域网（2026-11-19 新增）

审计（[`reports/network-security-vps-task-triage-2026-11-18.md`](../reports/network-security-vps-task-triage-2026-11-18.md) 简单项「端点广告配置说明」）
原先记录的限制是：`--advertise` 只支持固定 IPv4、外部端口必须与监听端口一致、动态 IP 需要重启。
本轮把这三条都改掉了，代价是部署形态要在命令里说清楚。

### 7.1 五种方式

A/B/C/D 是「端口从哪来」的四种方式，**E（DDNS）不是独立形态**：它是 A/B/C 里「地址会变」时的
写法。FRP 与 DDNS 同级，都是正式支持的方式。

| 方式 | 入站路径 | 宣告写法 | 典型命令 |
|---|---|---|---|
| **A. 公网 VPS** | 直连本机公网 IPv4 | `--advertise <公网IPv4>` | `wgp-node --bind 0.0.0.0:11010 --advertise 203.0.113.7` |
| **B. NAT 机（手动端口映射）** | 路由器把外部端口映射到本机 | 公网 IPv4 或 DDNS 域名 | `--advertise 203.0.113.7`（外部端口不同则再加三个 `--advertise-*-port`） |
| **C. FRP 穿透** | 公网中继 `frps` → `frpc` → 本机 | 中继地址 + 三个外部端口 | `--advertise relay.example.com --advertise-dht-port 21010 --advertise-stun-port 23478 --advertise-tcp-port 23481` |
| **D. 局域网 / 本机** | 同网段直连 | 私网地址 + 显式放宽 | `--advertise 192.168.1.10 --allow-local-endpoints` |
| **E. DDNS（跨方式）** | 同所在方式 | 域名 + 重解析周期 | `--advertise seed.example.com --ddns-refresh 300` |

方式 B 的操作清单（三条映射、固定内网 IP、hairpin/双层 NAT/CGNAT 三个坑）见
`server/deploy/DEPLOY.md` §10.1；方式 C 见 §10.2；方式 E 见 §10.4；验证清单见 §10.5。

**不支持的形态**：CGNAT（`100.64/10`）后面既无公网 IPv4 又无中继机；IPv6 广告（协议面 v1 只有 IPv4）。
这两种只能做「出站客户端」，或按形态 B 走中继。

### 7.2 与代码的对应关系

| 需求 | 代码落点 |
|---|---|
| 对外地址与端口分开 | `wgp_core::AdvertiseTarget`（`addr_v4` + `AdvertisePorts`），`AdvertiseTarget::spec()` 组装广告；端口 0 = 沿用本机 |
| DDNS 重解析 / 重宣告 | `server/wgp-node/src/server.rs::run()`：`AdvertiseSource::Dns` → 启动解析 + 周期重解析；地址变化时 `start_advertising(spec, base \| revision)`，纪元低 32 位当修订号 |
| 外部端口校验 | `resolve_opts()`：配了外部端口却没有 `--advertise`、或本机 `--stun none`/`--tcp none` 却配了对应外部端口 → 启动即报错 |
| 端点准入 | `wgp_dht::EndpointScope`（`addr.rs`）：默认只收公网；`scope_for_endpoints()` 按「用户自己配置的地址」自动判断本机/局域网形态 |
| FRP 资产 | `server/deploy/frp/frps.toml.example`、`frpc.toml.example`、`server/deploy/install-seed-frp.sh` |

### 7.3 FRP 的已知限制（必须写进运维认知）

FRP 的 UDP 代理按**访客**跟踪：种子主动推给别人的广告，在还没有任何访客时会丢。因此形态 B
的种子适合「被查询」（PING / FIND_SEEDS / FIND_VALUE 都正常），不适合当主动推送源；要让它尽快
进入别人的目录，给它配 `--peers` 指向一个能主动连到的公网种子。

另外：中继机的 `allowPorts` 白名单与云安全组必须放行三个远端端口（UDP DHT、UDP STUN、TCP 信令），
`frpc.toml` 里的 `localPort` 必须与 `wgp-node` 实际监听端口一致。这两条写错都会表现成「种子在线但
谁也连不上」。

### 7.4 验证状态

方式 A / B / D / E 的参数解析、广告组装、准入策略都有单元测试（`wgp-node` 的 `advertise_*` /
`allow_local_endpoints_flag`，`wgp-dht` 的 `addr::tests`、`endpoint_usability_filter`）。
**方式 C（FRP）与真实 DDNS 域名没有在真实中继 + 真实 NAT 上跑过**：脚本与配置是按 FRP 的公开
语义写的，第一次上线请照 `server/deploy/DEPLOY.md` §10.5 的检查表逐项确认，并把结果回填
[`18-NAT实测数据.md`](18-NAT实测数据.md) §7。

## 8. 怎么用：DDNS / FRP / 客户端（操作手册）

### 8.1 DDNS：让地址变化不再需要改配置

**适用**：家宽重播 IP、云主机弹性 IP、任何「域名不变但 A 记录会变」的场景，套在方式 A/B/C 上。

**一次性准备**（节点之外）：

1. 有一个域名，把它的 A 记录指向当前公网 IPv4；
2. 让 A 记录自动更新——三种任选：域名商的 DDNS 客户端（路由器内置最常见的那个）、
   云厂商 API 脚本、或本仓库 `server/deploy/wgp-refresh-advertise.sh`（它不更新 DNS，只在
   本地改写 `WGP_ADVERTISE`；有 DDNS 域名时**不需要**它）；
3. TTL 建议 60–300 秒（TTL 太长，别人缓存旧地址，重宣告也救不回来）。

**节点配置**：

```ini
# /etc/wgp-node/env
WGP_ADVERTISE=seed.example.com
WGP_DDNS_REFRESH=300          # 秒；0 = 只在启动时解析一次
```

```bash
sudo systemctl restart wgp-node-hobby
journalctl -u wgp-node-hobby -n 20 | grep -E 'DDNS|对外宣告'
```

期望看到 `DDNS：seed.example.com → <公网IP>` 与 `对外宣告 seed.example.com:11010 …`。
地址变化时会再打一条 `DDNS：… → <新IP>（原 Some(<旧IP>)），已用纪元 N 重新宣告`。

**客户端怎么写**：直接用域名，**不需要**关心 IP：

```bash
wgp-client join U/XXXX-XXXX-XXXX-XXXX -p udp://seed.example.com:11010
```

**排障**：

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志 `DDNS：… 暂时解析不出 IPv4，先以「不宣告」启动` | DNS 还没生效 / 网络未就绪 / 只有 AAAA | `dig +short A seed.example.com` 确认；等记录生效或检查 DDNS 客户端 |
| 日志有解析，但别人连不上 | 域名指向的 IP 不可入站（NAT 未映射，或 CGNAT） | 按 §7.1 的方式 B 加映射；`100.64/10` 只能走 FRP |
| 地址变了但别人还在连旧地址 | 纪元没变（进程没重解析）或 TTL 太长 | 确认 `WGP_DDNS_REFRESH>0`；调小 DNS TTL |
| `advertise 非法：既不是 IPv4 地址也不是合法域名` | 域名格式不合法（单段、含非法字符） | 用 `seed.example.com` 这种两段以上、只用字母数字与 `-` 的写法 |

### 8.2 FRP：没有公网 IPv4 时把种子「挂」到中继机上

**适用**：CGNAT、公司网、宿舍网——路由器上做映射也没用，因为根本没有可入站的公网 IPv4。
需要一台**有公网 IPv4** 的中继机（`frps`）+ 一份 token。

**步骤**（两份配置都在 `server/deploy/frp/`）：

1. **中继机**（`frps`，有公网 IP）：

   ```bash
   sudo install -d /etc/frp
   sudo cp server/deploy/frp/frps.toml.example /etc/frp/frps.toml
   sudo vi /etc/frp/frps.toml          # 改 auth.token；按需改 allowPorts
   sudo systemctl enable --now frps    # 或 frps -c /etc/frp/frps.toml
   ```

   放行：`TCP 7000`（控制口）+ `UDP 21010` + `UDP 23478` + `TCP 23481`（`allowPorts` 里的三个远端端口）。
   **云安全组与主机防火墙都要放行**。

2. **NAT 后面的种子机**（一条命令）：

   ```bash
   FRPS_ADDR=relay.example.com FRP_TOKEN='<与 frps 一致的长随机串>' \
     sudo -E bash server/deploy/install-seed-frp.sh
   ```

   脚本会：装 frpc + wgp-node → 写 `/etc/frp/frpc.toml`（0600）→ 写 systemd 单元（`--advertise`
   指向中继地址、三个 `--advertise-*-port` 写外部端口）→ 起服务 → 自检 → 打印客户端要用的种子行。

3. **客户端**：

   ```bash
   wgp-client join U/XXXX-XXXX-XXXX-XXXX -p udp://relay.example.com:21010
   # UDP 被封时加一条 TCP 兜底：-p udp://relay.example.com:21010 -p tcp://relay.example.com:23481
   ```

**FRP 的固有限制**（写在这里免得踩）：

- FRP 的 UDP 代理按「访客」跟踪：**种子主动推给别人的广告，在还没有访客时会丢**。
  所以 FRP 后面的种子擅长「被查询」（PING / FIND_SEEDS / 房间读写都正常），不擅长主动推送。
  要让它尽快进别人的目录，给它配 `--peers udp://<一台公网种子>:11010`。
- 中继机的带宽与稳定性决定体验；公共中继可能限速。
- 只映射了 UDP 没映射 TCP：UDP 全灭时没有信令兜底。

### 8.3 客户端怎么挑入口

| 你的环境 | `-p` 写法 | 额外参数 |
|---|---|---|
| 有公网种子/中继（域名或 IP） | `-p udp://seed.example.com:11010` | 无 |
| UDP 被封，但有 TCP 信令端口 | 再加 `-p tcp://seed.example.com:3481` | 无（打洞仍要 UDP） |
| 局域网/本机 | `-p udp://192.168.1.10:11010` | `--allow-local-endpoints` |
| 完全没有种子（实验） | `-p et://relay.example.com:11010` | 见 §8.4 |

### 8.4 没有种子时经 EasyTier 公共节点组临时网络（实验）

`et://` 入口在「一个真种子都测不通」时触发：客户端让 `wgp-et-fallback` 连公共 ET 节点，
用房间码派生的网络名/密钥组一张临时网，把本机的 11010/3478（以及打洞端口）透明送到对方；
开房的一方会在进程内起一个本地种子，加入方看到的就是「一个本地种子」。

前提与边界：

- 需要与客户端同目录（或 `WGP_ET_FALLBACK=<路径>` 指向）的 `wgp-et-fallback` 可执行文件——
  它在 `bridge/wgp-et-bridge` 这个**独立 workspace** 里，构建需要 `mesh-tun-proto` 检出与 `protoc`，
  所以不在主构建/CI 里；
- 流量经**公共中继**，带宽与稳定性不受本项目控制；`--no-et-fallback` 可关掉；
- 一条临时网只支持「房主 ⇄ 一个加入方」的数据面；多人需要真正的 ET relay（未做）；
- 不碰 TUN。

```bash
# 房主（没有可用 wgp 种子时）
wgp-client 开房 -n 房间 -k 密钥 -p et://relay.example.com:11010 --expose 25565
# 加入方
wgp-client join -n 房间 -k 密钥 -p et://relay.example.com:11010 --forward 25565
```

构建与验证方式见 `bridge/wgp-et-bridge/README.md`（含 `PROTOC` 与独立 workspace 的构建步骤）。
