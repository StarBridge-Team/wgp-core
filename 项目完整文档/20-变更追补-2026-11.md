# 2026-11-16 第二轮：身份证明 / TCP 兜底 / 多进程阶段 1

上一轮（11-15）留下四件「机制有了但不安全或不完整」的事。这一轮按依赖顺序收口，并在过程中修掉 3 个新发现的缺陷。

## 11. 探活身份证明（17 §11，线协议变更）

- **问题**：`PING/PONG` 之前只校验 `node_id == SHA256(pubkey)`，不证明私钥持有权；录一条旧报文换个源地址重放，就能把已知节点的地址簿条目指向攻击者。
- **做法**：一次一密挑战响应。新增 RPC `AUTH_CHALLENGE(0x3B)` / `AUTH_PROOF(0x3C)` / `AUTH_REJECT(0x3D)`；签名覆盖
  `"wgp/dht-auth/v1" ‖ version ‖ prover_id ‖ verifier_id ‖ nonce_echo ‖ prover_nonce ‖ txid`（117B）；
  证明里带 `prover_nonce` 让对方回证，1.5 RTT 双向认证。
- **闸门**：路由表与地址簿只有 `learn_verified` 一个写入口，只在「签名 + 一次性 nonce + 来源地址 + 期限」全过之后调用。
  `PING` 只为存活与兼容而应答，`PONG`/`STORE` 不再学习。
- **升级**：版本轴 = 类型号（老节点按未知类型丢弃）；广告新增 `FLAG_AUTH_V1` 能力位；默认严格，`--allow-legacy-identity`
  显式回退旧 PING/PONG；严格模式失败时用一次只读 PING 区分「旧版本」与「不可达」（`RpcError::Unverified` vs `Timeout`）。
- 落点：`wgp-proto` 三个包体 + `auth_signing_message`，`wgp-dht/src/auth.rs`（新），`node.rs` 的 `Pending::Auth` / `issued` / `AuthGate`。
- 测试：伪造（冒用 node_id / 冒用公钥）、重放（旧证明、跨挑战、回证跨来源）、错误来源恢复、版本拒绝、洪流限速、
  严格模式不学习、兼容模式学习、换端点恢复，共 23 个新用例。

## 12. UDP 被封锁时的入房路径

- `Transport::{Udp, Tcp}` 贯穿 `DhtNode`（`set_signaling_transport` 分派 `ping/find_node/store/find_value/forward_to/find_seeds`）
  与 `RoomRuntime`（`with_transport`、`StorageCandidate.transport`）。
- 复用同一套 RPC 报文与 `u16 BE` 长度前缀帧；没有新增任何线格式。
- 客户端：`-p tcp://<种子>:3481` 即走 TCP 信令；bootstrap / 选点 / `fetch`·`store`·`renew` 都能落到 TCP。
  没有可用 TCP 种子、种子不宣告 `tcp_port`、UDP 全灭等情况都在开始阶段给出可读报错，而不是等到入表超时。
- **明确记录的限制**：TCP 不能完成「报道 → 锚点」这一跳（Forward 需要存储节点地址簿里的 UDP 目标），
  也无法做邻居扩散；打洞与数据面仍然离不开 UDP。见 12 §6.5。
- 测试：`room_readwrite_works_over_tcp_when_udp_endpoint_is_dead`（存储节点的 UDP 端口是死的，读写仍成功）、
  `tcp_room_reports_store_failure_when_seed_has_no_tcp_listener`、客户端候选选择在 TCP 模式下跳过无 TCP 端口的种子。

## 13. 路由维护

## 17. STUN 响应绑定与投毒防护（审计 M1）

- **问题**：客户端 `probe_observer` 只校验 `tx_id`。攻击者/反射器只要能抢先发出一枚「同 txid 的包」，
  就能把「我的公网端点」写成任意值——打洞被引向错误地址，或 NAT 判定被做成锥形/对称之一。
  另外 txid 是**可预测的**（取自对端 NodeId 前缀），步长三连测的 nonce 还是常量。
- **做法**（`kernel/wgp-core/src/engine/nat_probe.rs`）：
  1. 新增 `parse_observer_response(buf, tx_id, echo)`：类型必须是 Binding **Success Response**（反射回来的
     请求带同一个 txid 和 cookie，只差类型）、txid 一致、带扩展时 **nonce 必须原样回显**、映射地址可用（端口非 0、地址非未指定）。
  2. `probe_observer_within` 在超时内循环收包：**来源地址必须等于被探测的观察者**，不是就继续等（不再「读第一枚
     就下结论」）。超时/坏包都不产生报告。
  3. `fresh_probe_ids()`：每次探测用 CSPRNG 生成 txid + nonce；`learn_step` 三连测各自独立；
     `orchestrator` 的观察者探测也改用它（原来是对端 NodeId 前缀）。
- **测试**（`wgp-core`，5 个新用例）：`response_binding_matrix`（类型/txid/nonce/畸形映射地址逐项）、
  `forged_reply_from_other_source_is_ignored`（另一台主机持续发同 txid 的「合法」应答，最终报告仍是真观察者给的）、
  `observer_that_does_not_echo_nonce_is_rejected`、`reflected_request_is_not_a_report`、原有回环互通用例保持通过。
- **边界**：这挡的是「伪造/重放应答」；不挡观察者本人作弊（它本来就知道你的地址），也不做公网 STUN 服务器的可信度评估。

## 18. 端点地址准入（审计 M2）

- **问题**：广告与 `NEIGHBORS` 转述里的地址只过滤了 `0.0.0.0`/广播/组播。任何人都能把 `127.0.0.1`、`10.x`、
  `169.254.x`、`100.64/10`、文档网段写进签名广告并转述出去，收到的人各做一次注定失败的探活/打洞。
- **做法**：新增 `kernel/wgp-dht/src/addr.rs`：
  - `EndpointScope::{Public, LocalNetwork}`：`Public` 只收公网 IPv4（排除回环、RFC1918、链路本地、CGNAT、
    0/8、IETF 协议分配段、三个 TEST-NET、198.18/15、组播、240/4、IPv6）；`LocalNetwork` 额外放行回环/私网/链路本地，
    仍然拒 CGNAT 与保留段。
  - `EndpointScope::from_local_bind()`：绑在回环/私网地址上的节点自动取 `LocalNetwork`（本机联调与单元测试不必逐个设置）；
    绑 `0.0.0.0`/公网仍是严格默认。
  - `scope_for_endpoints()`：按**用户自己配置的地址**（`--peers`、`--storage`、`--advertise`）推断形态。
  - `DhtNode::set_endpoint_scope()`；`examine_advert` 与 `lookup_node` 的转述路径都按当前策略判定。
- **部署层**：`wgp-node --allow-local-endpoints`（另按 advertise/peers/bind 自动判断）、
  `wgp-client --allow-local-endpoints`（默认按解析到的种子地址判断）、agent 按种子/存储地址判断。
- **测试**：`addr::tests`（审计列出的每个特殊网段逐条断言 + 局域网策略 + u8 往返）、
  `endpoint_usability_filter`（重写为两种策略的对照矩阵）。

## 19. 房间成员容量与 STORE 静默截断（审计 M5）

- **问题**：`RoomRecord::encode` 写 `members.len() as u8`（>255 静默回绕），整块记录又被
  `StoreBody::encode` 静默截断到 1024B。两种都产生「签名看起来有效、成员表其实已被改」的静默损坏；
  `add_member` 没有任何上限，满员后表现为「一直补报道、永远进不去」。
- **做法**：
  - `MAX_ROOM_MEMBERS = 12`（64B 签名 + 50B 记录头 + 12×64B 成员 + 1B pow 长度 = 883B，留 141B 给 PoW 凭证）。
  - `RoomRecord::try_encode() -> Option<Vec<u8>>`：成员越界、PoW 过长、整块超 `STORE_VALUE_MAX` 一律 `None`；
    `encode()` 是「已校验路径」的包装（越界即 panic，测试里用）。
  - `sign_room()` 改为返回 `Option<Vec<u8>>`；`RoomRuntime::publish` 映射为 `RoomError::RecordTooLarge`。
  - `add_member` 满员返回 `RoomError::RoomFull`，**不覆盖**存储节点上的旧记录；`decode` 侧同样拒绝超限 count。
- **测试**：`record_encoding_refuses_to_truncate`（上限内可往返、13 个成员/N 超 255B PoW 均显式失败、
  篡改 count 被拒、整块 ≤ 1024）、`add_member_refuses_when_room_is_full`（满员失败且旧记录不变）。

## 20. 入站限速统一与放大应答预算（审计 M6 + M3 的可落地部分）

- **M6**：DHT socket 上的 STUN 应答此前**完全不限速**，同一个 socket 既能被刷上行流量又能被当放大器。
  现在 `kernel/wgp-dht/src/ratelimit.rs` 提供统一闸门（单源窗口额度 + 全局每秒额度 + 源表硬上限，超限静默丢弃），
  `ObserverServer` 与 DHT 读循环共用它；`DhtNode::set_stun_rate_policy()` 供运维覆盖。
- **M3 缓解**：`ByteBudget` 按源 IP 与全局限制「放大应答」的字节速率（NEIGHBORS/VALUE/SEEDS 走
  `sink_send_amplified`，TCP 出口不记账——那条路要完成三次握手，不可伪造源）。
  默认单源 32 KiB/s、全局 1 MiB/s；一次完整迭代查找约 3 KB，正常查询不受影响。
  **真正的解法是给请求加源地址 cookie，那要改线协议**，仍留在待决策清单里。
- **测试**：`ratelimit::tests`（单源额度与源端口无关、全局限速挡分布式洪流、源表硬上限、
  字节预算的单源/全局边界与窗口滚动）。

## 21. 种子节点部署：外部端口 / DDNS / 局域网（产品线的 FRP·NAT·DDNS 要求）

- **内核**（`wgp-core`）：新增 `AdvertiseTarget { addr_v4, ports: AdvertisePorts }` 与
  `AdvertiseTarget::spec(local_ports, hobby)`：外部端口 0 = 沿用本机端口，本机没开的能力对外一律 0；

- **节点**（`wgp-node`）：
  - `--advertise` 现在接受固定 IPv4 / **DDNS 域名** / `none`；域名在启动时解析，之后每

  - `--advertise-dht-port/-stun-port/-tcp-port`：FRP / 端口映射用。配了外部端口却没有 `--advertise`、
    或本机 `--stun none`/`--tcp none` 却配了对应外部端口，启动即报错（避免广告指向空端口）。
  - `--allow-local-endpoints`：局域网 / 本机形态的准入放宽。
  - 就绪日志打印「广告地址:端口（DHT/STUN/TCP）」与准入策略，FRP 形态额外提示「请确认中继端确实转发了这些端口」。
- **资产**：`server/deploy/frp/frps.toml.example`、`frpc.toml.example`（token 鉴权 + `allowPorts` 白名单 +
  三个 proxy）、`server/deploy/install-seed-frp.sh`（NAT 端一键：装 frpc + wgp-node、写单元、起服务、
  自检、打印客户端种子行、把 FRP 的真实限制写在结尾）。
- **文档**：`server/deploy/DEPLOY.md` 新增 §10（四种拓扑 + FRP 限制 + 验证清单），
  `项目完整文档/17-部署与运维.md` 新增 §7（与代码的对应关系 + 验证状态）。
- **测试**：`wgp-node` 的 `advertise_accepts_ddns_hostname`、
  `advertise_external_ports_require_advertise_and_matching_local_service`、`allow_local_endpoints_flag`；
  `advertise_is_parsed_and_validated` 补齐新的非法输入。
- **明确未做**：CGNAT 后面的种子仍不可入站（除非走 FRP），IPv6 广告未实现，UPnP/NAT-PMP 自动打洞未实现，
  `--advertise auto`（用 STUN 自测外部地址）没做——需要把客户端侧探测栈编进种子二进制，收益不如 DDNS。

### 24.2 wgp-et-bridge

| 变化 | 说明 |
|---|---|
| 数据帧走数据报通道 | 控制帧（握手/RPC/Ping/Pong）走可靠流；`PacketType::Data` 走 `TunnelHandle::send_dgram`（16B 头 + 载荷，无长度前缀）。超长或队列满自动退回可靠流，接收端两条通道都读，回退不丢帧——避免「TCP over TCP」 |
| 确定性开流 | PeerId 较小的一方发起（`should_open_et_stream` / `establish_et_stream`），两端独立计算必然相反，不需要协商，也不会开出两条流 |
| IP 帧与路由交接面 | IP 包用命令发出、以 `P2pEvent::InboundIpPacket` 事件收回，这就是将来接 TUN 的接口（本轮不写网卡） |
| 验收 | 回环上：打洞 → ET 握手 → 双方宣告虚拟 IP → 各自路由表看到对方 → 双向 IP 帧 → 第三节点加入可见、离开后 `PeerDown` 且路由清理 |
| 新增库 API | `wgp-port`：`Tunnel::take_dgrams()`（取走入站数据报接收端并换空通道，供自己按端口分流的调用方使用） |

### 24.3 仍然没做（明确边界）

- **TUN 虚拟网卡**：Windows 需要 Wintun 驱动与管理权限；Linux 需要 `/dev/net/tun` + 路由接管。桥接只把 IP 包以事件交出来。
- **与官方 EasyTier 节点互通**：需要一台真实官方节点对测；轻量客户端是「叶子」——`to_peer_id` 不是自己的帧直接丢，不替别人转发，两个叶子之间必须有真正的 ET relay。
- **「加入 ET 网络」的主 CLI**：仍是库 + 测试与 examples，没有面向用户的命令。
- **一条隧道只有一个数据报消费者**：`take_dgrams` 只能取一次，所以同一对节点上第一条 ET 流吃数据报、后续流走可靠流。

## 25. 部署方式的调整：不替用户装 frpc，改支持 PROXY protocol v2

使用方明确指出：第三方 FRP 服务的客户端版本/参数由服务商决定，**自己下一个 frpc 往往连不上**，
所以不要做「下载并配置 frpc」这类自动化。调整如下：

| 变化 | 说明 |
|---|---|
| 删除自动安装 | `server/deploy/install-seed-frp.sh`（一键装 frpc + 写 systemd + 自检）移除；`frp/*.toml.example` 保留为**自建时**的参考，并在文件头写明「本项目不下载、不安装、不管理 frpc/frps」 |
| 节点侧保留什么 | 只需两件事：① `--advertise <中继地址或 DDNS 域名>` + 三个 `--advertise-*-port`（外部端口）；② 若代理注入 PROXY protocol v2，加 `--proxy-protocol v2` |
| 新增 PROXY protocol v2 | `kernel/wgp-dht/src/proxy_protocol.rs`：IPv4/IPv6、TCP/UDP、`LOCAL`、截断与伪造拒绝；观察者用头里的真实客户端地址出映射报告与限速，应答仍回给代理；TCP 信令先 `peek` 确认签名再消费头（没配代理的客户端不受影响） |
| 安全边界 | 默认关闭。打开等于「让对端自称来源」——只能用于「本端口只可能被可信代理访问」的部署；关着时带头的报文当坏包忽略（有用例钉住） |
| 它不解决什么 | TCP 信令的源地址给不出该客户端的 UDP 端口，所以不能据此填地址簿的 UDP 端点；Forward 中转仍受方式 C 的固有限制 |
| 文档 | `DEPLOY.md` §10.2 重写（你用什么 frpc 由服务商决定）、新增 §10.6；`17-部署与运维.md` §8.2 同步、新增 §8.5 |

## 26. ET 回退（S1-S4）：没有 wgp 种子时经 EasyTier 公共节点组临时网络

方案与取舍见 [`reports/et-fallback-seed-feasibility-2026-11-19.md`](../reports/et-fallback-seed-feasibility-2026-11-19.md)：
不用 ET 的 Port Forward（库里是占位实现），改成「固定端口 UDP ⇄ ET 自定义帧」的桥。

| 阶段 | 内容 | 验收 |
|---|---|---|
| S1 | `bridge/wgp-et-bridge/src/fallback.rs`：no-tun 连公共 ET 节点，`11010`/`3478`/打洞端口透明送到对端；网络名/密钥由房间键派生；打洞端口 = `42100 + peer_id % 900` | `tests/fallback_bridge.rs`：两桥经一条 ET 链路 UDP 往返 + 打洞端口到应用 |

| S2 | 房主进程内**本地种子**（DHT 127.0.0.1:11010 + 观察者 3478） | `tests/fallback_room.rs`：加入方经桥 PING（含身份证明握手）、读房间、报道经桥入锚点入表（1.5s） |
| S3 | 客户端：`-p et://host:port` 收集入口；**一个真种子都测不通**且给了 et:// 才触发；`--no-et-fallback` 可关；桥拉不起来给可读错误后按原路失败 | 客户端 9 个单测（解析/触发条件/READY/路径查找/派生/help/门控 e2e） |

边界（写进 README 与文档）：一条桥只支持一个对端参与数据面；同机不能跑两个回退客户端
（抢同一打洞端口）；`connect_peer` 重连时旧 socket 未释放会重复 bind 失败（supervise 会重试，
没有彻底解决）；两侧必须同时在线；不碰 TUN。
