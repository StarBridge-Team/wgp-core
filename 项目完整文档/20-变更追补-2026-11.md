## 2. `kernel/wgp-proto`（10 号文档）

- `packet.rs`：新增 `tunnel` 模块——数据面隧道报文的类型号 `0x40` 与 12B 外层头（`magic(2) | type | flags | counter(8)`）；
  新增 `SeedAdvertiseV2` / `seed_advertise_v2`（type `0x21`，123B，自带公钥）。V1 保留作对照，线上不用。
- `dht.rs`：新增 RPC `FIND_SEEDS(0x39)` / `SEEDS(0x3A)`，`FindSeedsBody`（target + 填充，`quota()` 保证应答不长于请求）、
  `SeedsBody`（至多 8 条广告原文）。
- `consts.rs`：新增 `SEED_ADV_DOMAIN`（广告签名的域分隔前缀）。

## 3. `kernel/wgp-crypto`（11 号文档）

- 新增 `tunnel.rs`：`derive_tunnel(session_key, local, remote)` 用 HKDF 从会话密钥派生两个方向各自的 AES-256-GCM 密钥与
  nonce 前缀；`TunnelSealer / TunnelOpener`；`ReplayWindow`（验签通过后才推进的重放窗口）。

## 4. `kernel/wgp-punch`（13 号文档）

- `budget.rs`：`reserve_round()` / `refund_round()`（每次打洞会话从 10 分钟窗口预扣一轮、结束归还）、
  `try_acquire_keepalive()`（保活只过窗口闸门）。此前「轮」从不复位。
- `wave.rs`：只要有模型，不论置信度高低，第一波首包都直打预测中心。

## 5. `kernel/wgp-dht`（12 号文档）

- `advertise.rs`：`AdvertiseSpec`、`sign_advertise_v2`、`verify_advertise_v2`（严格验签，返回广告主 NodeId）。
- 新增 `directory.rs`：`SeedDirectory` / `SeedInfo`——纯数据结构，管「一条广告该不该进、怎么更新、何时逐出」
  （纪元只进不退、换地址要探活、一个端点一个身份、64 条上限、入口种子置顶、连续 3 次探活失败逐出）。
- `node.rs`：读循环识别推送来的广告；应答 `FIND_SEEDS`；新增 `start_advertising`、`find_seeds`、`discover`、`seek_seeds`、
  `lookup_node`（迭代 FIND_NODE）、`spread`、`spawn_maintenance`（20s 探活 / 60s 推送 / 5min 索取）、`seeds`、`watch_seeds`、`pin_seeds`。
  `discover` 结束时把自己的广告推给已知种子。
- `kbucket.rs`：`RoutingTable::remove`。
- `room.rs`：新增 `LeaseWatch`（成员只看「本地观测到租约多久没变」）。
- `runtime.rs`：`JoinRequest` 升级为 v2（携带 room_key 而非房间码，定长 163B，校验 `member_id == SHA256(pubkey)`）；
  `try_takeover(code, current, unchanged_ms, now_ms)`；锚点首拍立即续期；新增 `RoomRuntime::locate` 与 `StorageCandidate` / `StoragePick`
  （已有房间则跟随；否则按中转能力分档——明确可中转 > 不知道 > 明确不中转，同档取离房间键最近者）。
- `net_test.rs`：新增 `seed_discovery` 模块（12 个回环网络用例）。

12 号文档「已知问题」第 12 条（JoinRequest 头注释与签名域不一致）随 v2 消失。

## 6. `kernel/wgp-core`（14 号文档）

- `link.rs`：`PunchedLink` 新增 `peer_addr`。
- `engine.rs`：每次 `new_link` 用独立的一轮预算并归还余额；窗口耗尽时报 `LinkLost{BudgetExhausted}`；10 分钟回填定时器；
  `join_room` 等待 6s 并每 1.5s 补发报道；`NodeConfig` 新增 `advertise / advertise_epoch / peers`，`run_node` 接线宣告与引导
  （一个引导端点都没问到时按 0 / 0.3 / 0.7 / 1.5 / 3 / 6 秒重试）。
- `engine/punch_runner.rs`：监听窗口内丢弃不算数的包后继续等，不再被自己的探针折返提前结束。
- `engine/keepalive.rs`：重写——`fair_share_interval_ms`，多条链路按份额分摊窗口预算。
- `orchestrator.rs`：新增 `wait_incoming`；`connect_peer` 能消化提前到达的 Reveal（修阶段漂移死锁）；端点帧先验长度（修越界 panic）；
  对端无步长模型时用实测端口兜底建模。
- `transport/tcp.rs`：TCP 链路交付前开启系统 keepalive（30s）；打洞改为同端口「监听 + 主动连接」（监听口先验后发；
  socket 开端口共用；一次 `punch_port` 总时限 990ms）。原实现在 Linux 上打不通，详见 `docs/14` §12.1。
- 新增 `transport/test_ports.rs`（仅测试编译）：测试用的端口在系统动态端口范围之下随机取、进程内不重复。

## 7. `bridge/wgp-port`（新增，数据面）

内核交付的 `PunchedLink` 在这里变成可用的隧道。分层：`forward ⇄ mux ⇄ link ⇄ PunchedLink`。

| 文件 | 行数 | 职责 |
|---|---|---|
| `src/lib.rs` | 63 | 模块装配与对外导出；`CloseReason`、`close_code` |
| `src/ranges.rs` | 263 | `RangeSet`：确认区间与缺口的区间集合 |
| `src/frame.rs` | 607 | 链路层帧（ACK / STREAM / DGRAM / CLOSE）与复用层帧（HELLO / OPEN / DATA / FIN / RST / WINDOW）的编解码 |
| `src/arq.rs` | 1095 | UDP 载体上的可靠层（纯状态机）：报文号不复用、选择确认、报文数 / 时间阈值判丢、超时探测、NewReno；不发周期心跳 |
| `src/link.rs` | 427 | 载体适配：UDP 收包按类型字节分流（保活探针 / 隧道报文）、逐包认证 + 重放窗口、对端地址漂移跟随；TCP 为长度前缀的加密记录流 |
| `src/mux.rs` | 746 | `Tunnel::from_link`：多条双向流 + 逐流额度流控（256KiB）、半关闭、重置；数据报旁路；`TunnelHandle` |
| `src/forward.rs` | 614 | `PortHub`（即内核的 `LinkSink`）：暴露 / 转发，TCP 与 UDP；同一对端重新打洞时以新代旧 |
| `tests/tunnel.rs`、`tests/forward.rs`、`tests/common/mod.rs` | 1190 | 28 个集成测试（真实回环 socket），含「种子 + 观察者 + 双引擎自动打洞 → 转发」的全链路用例 |
| `examples/echo_tool.rs` | 201 | 联调用的回显服务与校验客户端 |

加密：外层 12B 头作 AAD，AES-256-GCM，计数器即 nonce 低 8 字节；密钥见 §3。没有按 00 D3 用 QUIC——理由见 14 §12.1。

## 8. `server/wgp-node`（15 号文档）

- 新选项 `--advertise <IPv4|none>`、`--peers <list>`（可重复），对应 `WGP_ADVERTISE` / `WGP_PEERS` 与配置文件键。
- 广告纪元：启动计数存在身份文件旁的 `node_identity.epoch`（`next_advertise_epoch`）。
- 启动日志写明是否宣告与引导端点；种子目录成员变化时记一笔。
- 新增对 `wgp-proto` 的依赖（解析端点与中文域名）。

## 9. `client/wgp-client`（16 号文档）

基本重写（611 → 1363 行）：

- `SilentSink` 换成 `wgp_port::PortHub`；新选项 `--expose / --forward / --expose-udp / --forward-udp`。
- 逐对端链路监管 `supervise_peer`：协商 → 等结果 → 失败按 3s / 10s / 30s 退避重试（至多 3 次）；
  全程挂着 `wait_incoming` 响应对端发起的重连。
- 启动时做种子发现；没给 `--observer` 时自动选用发现到的观察者；存储节点由 `RoomRuntime::locate` 按房间键选定；
  选中贡献模式种子时给出告警。
